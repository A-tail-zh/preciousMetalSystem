# 生产出库批次剩余计划上限修复与验收

## 问题与规则

生产出库的自动建批页面原先默认产品组总目标，输入上限固定2147483647，没有显示其他有效批次已经占用的计划。后端建批事务已校验剩余计划，但页面反馈太晚。

新建批次按“产品组目标－已分配有效批次计划”限制，不能按领料克重或实际产出件数推算计划占用：

- 目标100、已分配30：默认70，最大70。
- 已分配30+70：剩余0，禁止继续自动新建，改选已有加工记录领料或补料。
- 空自动批次取消后释放其计划份额。
- 拆分父批、合并来源批及已取消批不重复计入；有效结果批、已完工及异常终止的计划口径与后端既有建批校验保持一致。
- 原100件批次只完成30件时，剩余70件属于同一批次的责任；不能据此再新建70件占用额外计划，应继续原批次或按拆分流程处理。

## 实现

`StorageOrderService.options`为产品组返回`allocatedQuantity`和`remainingQuantity`，范围限定当前工厂。`OrderEditor.vue`以剩余计划作为默认值、输入最大值和确认前校验；剩余0时禁用数量框及新增物料，并显示明确的份额用尽错误。已经生成的本次加工记录保持原计划锁定，不因剩余额度包含自身而被改成0。

保留后端工厂锁和提交时的当前计划重核，应对多人并发或页面数据过期。页面限制不能替代后端校验，本次没有放宽或绕过后端规则。数据库版本仍为V85，无迁移和历史数据回填。
