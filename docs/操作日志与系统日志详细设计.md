# 操作日志与系统日志详细设计

设计日期：2026-10-13。状态：用户已批准实施；2026-10-14已接入日志模块，验收见《日志管理使用与验收说明》。依据当前若依Spring Boot后端、Vue前端、本地MySQL/Redis和用户确认的工厂隔离规则。

## 1. 目标与现状

目标：回答“谁在什么时间，对哪个工厂的哪张单据做了什么，是否成功，失败原因是什么，怎样找到对应运行异常”。日志是管理和诊断依据，不能代替库存流水、审核历史和报工事实。

现有能力：sys_oper_log与@Log记录操作，sys_logininfor记录登录；monitor/operlog、monitor/logininfor已有页面和接口，但自定义业务侧栏没有入口。LogAspect异步入库，请求与响应各截断至2000字符；记录用户名、URL、类型、结果和耗时，未提供工厂ID、业务对象和统一追踪ID。失败校验和权限拒绝可能发生在业务切面执行前。logback按日保留60天文件，INFO文件只收INFO、错误文件只收ERROR，WARN可能只进控制台。调试级别的Mapper输出可能打印业务字段，不宜常开。

仓储、工单等关键写入已有@Log，但这不等于有完整前后差异、事务结果和故障串联。实施前逐个接口建立覆盖清单，不覆盖或改写当前未提交的用户修改。

## 2. 导航、权限和工厂范围

新增“系统管理”分组：操作日志、登录日志、系统运行日志、日志配置。沿用正常比例布局及16条分页；这些管理页允许必要的筛选工具，不套用基础资料页面不得增搜索栏的原型限制。

| 用户 | 可查看内容 | 可执行操作 |
|---|---|---|
| 超级管理员 | 全部操作、登录、系统运行和清理执行记录 | 查询、详情、授权范围内导出、配置留存和查看采集状态 |
| 本厂获授权管理员 | 本厂操作日志 | 查询、详情；独立授予导出权限后导出本厂数据 |
| 未获日志权限人员 | 无日志数据 | 页面入口隐藏，直接接口403 |

工厂管理员不是按角色名称判断，使用明确分配的日志权限+有效所属工厂。普通账号即使获同名权限也只限本厂；系统运行与登录日志本期只允许超级管理员。默认不自动给演示角色授予新权限。

操作日志保存操作发生时的actorFactoryId、businessFactoryId。业务数据修改所属工厂时，将来源和目标分别写scope明细，只有超级管理员可完整查看跨厂操作；本厂管理员只查看单厂事件，不能看到另一工厂的差异。共享产品、物料、工序操作：普通人员记录到本人当时所属工厂；超级管理员共享维护属于全局日志，不向本厂管理员展示。超级管理员对明确某工厂单据的操作记录在该工厂。

工厂范围由服务端对象解析，不信任请求factoryId。旧日志不推断历史归属，保留为未归属日志，仅超级管理员可查看。人员转厂不改变历史日志归属。原monitor接口的列表、详情、导出同样改造校验，不能绕过新页面；原clean与remove接口本期停用，不能清空审计历史。

## 3. 操作日志页面与采集规则

列表列：时间、工厂、操作人、模块、操作类型、业务单号/对象、结果、耗时(ms)、追踪ID、操作（详情）。查询：时间范围、工厂（超级管理员）、操作人、模块、类型、结果、业务单号、追踪ID。默认最近7天，排序时间倒序、ID倒序；每次查询最多31天，分页最大100。名称、单号模糊查询，追踪ID精确查询。

详情分区：操作摘要、业务对象、字段变更、失败原因、请求摘要与响应摘要、技术定位。创建/修改/删除、审核通过/驳回/重提、启停、密码重置、授权、保存报价、入库出库还库、库存调整、结算、冲销、预警处理、模板下载、导入、日志导出和配置修改均进入覆盖清单。下载、导入记录文件名、行数、文件哈希，不保存文件二进制。

日常列表、下拉和看板刷新不逐次存业务操作日志，避免放大数据量；敏感人员/权限详情查询及日志查看、导出留访问审计。失败的写入、越权尝试均记录，即使未进入Controller。

记录结果分SUCCESS、BUSINESS_REJECTED、VALIDATION_REJECTED、ACCESS_DENIED、SYSTEM_ERROR。HTTP200中code非200不能被当成成功。成功以事务提交为准，回滚不得生成成功操作。重复UUID返回已有结果标记replayed=true，不伪造第二次库存过账。一次请求只产生一个业务操作事件，过滤器仅补齐切面未记录的失败，按traceId+eventKey去重；库存、报工、预警等关联对象作为同一事件的对象清单。

字段差异从数据库实际值及提交后的值获取，采用允许清单；记录字段名称、旧值、新值和单位。订单明细按稳定ID匹配，不以显示序号判断对象。损耗、库存金额和重量保留精确十进制字符串。多明细最多记录100项，另存总项数与truncated标记，不生成超长请求记录。

## 4. 登录、系统运行与故障追踪

登录日志：登录成功/失败、验证码失败、账号禁用、退出、会话失效、密码或角色变更导致令牌失效。显示账号、时间、结果、原因分类、来源IP、浏览器、traceId；不记录验证码内容、密码或完整令牌。用户名不存在与密码错误对外使用统一提示，日志也不向工厂人员开放。

系统运行列表：时间、级别(INFO/WARN/ERROR)、服务、组件、事件类型、摘要、耗时、traceId、详情。可按时间、级别、组件、traceId筛选；默认最近24小时，最长7天，分页最大100。详情展示已脱敏异常类型、根因、受控长度调用栈和关联操作入口，不提供任意服务器路径读取或任意命令执行。

覆盖启动/停止、数据库和Redis连接失败、事务回滚、未处理异常、权限拒绝、慢请求、慢SQL摘要、异步日志积压、导入失败、库存冲销失败、定时清理结果与磁盘空间告警。业务规则拒绝为WARN摘要，系统异常为ERROR及调用栈；不为每个正常HTTP请求新增数据库系统日志。

每个HTTP请求由服务端生成32位小写十六进制traceId，写入MDC、响应头X-Trace-Id及错误响应traceId；保持现有code/msg/data结构，不改变HTTP业务协议。前端在失败提示中提供复制追踪ID，统一错误拦截器处理。异步任务复制MDC，线程退出后清除，防止串号。客户端不控制日志正文或traceId；新增前端错误上报为后续范围，本期不开放匿名上传接口。

统一文件行格式包含上海时区日期时间、level、service、thread、traceId、logger和摘要，JSON行便于结构化采集；调用栈置于JSON字段。INFO及以上统一运行文件收WARN，ERROR同时写独立错误文件，登录审计写独立文件。按日期+大小滚动，单文件50MB、gzip归档。业务Mapper默认INFO，不打印完整SQL参数；慢SQL仅记录SQL模板、耗时和数据源，无绑定参数。慢请求阈值2000ms、慢SQL阈值1000ms，可配置。

定位示例：用户复制失败追踪ID→操作日志显示冲销被拒绝和单据号→关联运行日志查看拒绝原因或异常→核对库存流水与后续引用。连接失败时查询运行文件，不能假设数据库日志页面仍可访问。

## 5. 数据与接口

复用sys_oper_log、sys_logininfor，追加字段；新增迁移版本在实施前检查Flyway，实施时已有V1～V16，本次使用V17，不改已执行脚本。

操作日志追加：traceId、actorUserId、actorFactoryId、businessFactoryId、moduleCode、actionCode、eventKey、resultCode、businessCode、objectType、对象清单JSON、changesJSON、errorCategory、replayed、truncated、schemaVersion。另建scope关系保存多工厂ID；旧原始字段保留兼容但返回时统一脱敏。actorName、factoryName为历史快照，删除人员不删除日志。

新增audit_outbox：eventId(UUID)、脱敏事件JSON、状态、重试次数、创建时间、下次重试时间。关键业务成功审计与业务变更在同一事务写outbox；outbox写入失败则关键写入回滚，返回可追踪错误，不静默丢失过账审计。提交后消费者按eventId唯一键写sys_oper_log，成功标记投递；1/5/30/120/600秒重试，之后每10分钟重试并告警，不直接丢弃。宕机重启继续投递，事件不重复。

失败、无事务查询与登录事件独立事务/异步有限队列记录；数据库不可用时写脱敏本地audit-fallback JSON行，恢复后导入并按eventId去重。失败日志写入问题不得覆盖原始业务错误。运行日志文件为主，单独消费者增量写sys_runtime_log，保存文件游标和唯一eventId，防止重启重复；采集器自身错误只写独立本地文件，避免递归采集。

sys_runtime_log：id、eventId、eventTime、level、service、component、eventType、summary、traceId、exceptionClass、脱敏detailJSON、costMs、createTime。不保存请求完整body或用户会话。

| 接口 | 功能与权限 |
|---|---|
| GET /monitor/operlog/list、/{id} | 操作列表/详情，monitor:operlog:list/query，强制工厂范围 |
| POST /monitor/operlog/export | 当前筛选导出，monitor:operlog:export，强制工厂范围 |
| GET /monitor/logininfor/list | 登录日志，仅超级管理员且有列表权限 |
| GET /monitor/runtime-log/list、/{id} | 系统运行日志，仅超级管理员，monitor:runtime-log:list/query |
| GET /monitor/runtime-log/trace/{traceId} | 同一请求时间线，仅超级管理员；跨厂事件不向普通账号返回 |
| POST /monitor/runtime-log/export | 受限导出，仅超级管理员+导出权限 |
| GET/PUT /monitor/log-config | 配置和采集状态，仅超级管理员+查询/编辑权限 |
| GET /monitor/log-config/cleanup-history | 自动清理历史与错误，仅超级管理员 |

主键、长整数和十进制返回字符串，版本整数，时间yyyy-MM-dd HH:mm:ss，服务器上海时区。配置编辑携带版本防覆盖；系统日志是只读数据，不能在线改动条目内容。导出最大10000行，同一账号每分钟最多一次；超限提示缩小条件，不默默截断。Excel文本防止等号、加号、减号、@被解释为公式。

## 6. 脱敏、可信性与保留

禁止记录：任何密码字段、临时密码、验证码、Authorization/Cookie、token、secret、数据库和Redis密码、连接串凭据、上传文件正文。递归按字段名大小写归一匹配，兼顾嵌套DTO、集合、返回对象和URL查询串，先脱敏再截断。手机号默认显示前三后四；系统管理员不提供“取消脱敏”入口。CR/LF等控制字符转义，日志文本用纯文本渲染，禁止HTML执行。

凭据脱敏不靠单一@Log.excludeParamNames；定期用测试secret哨兵扫描DB、运行文件和导出。调用栈、异常消息也检查凭据。请求摘要与响应摘要各最多4KB，差异JSON最多16KB，栈最多32KB；明确truncated标志和原项数。

审计日志只允许采集器追加，业务人员无修改与删除入口；管理员也不提供任意清空。自动清理作为受审计运维操作。无需引入第三方日志平台或新的消息中间件，沿用MySQL、应用任务调度和滚动文件；本机管理员仍可修改文件，不能声称达到不可篡改合规存储。

默认保留：操作与登录数据库180天，运行日志数据库30天，运行/错误/登录文件60天，关键审计归档文件365天。操作与登录DB删除前先压缩归档，生成清单、行数和SHA-256，校验后按ID分批删除，每批1000条；归档失败不删除。每天上海时间02:30执行，服务启动补查漏执行日期，使用分布式任务锁防重复。fallback文件只有成功回补后才参与过期清理。待投递outbox不按时间删除，已投递保留7天。

运行文件总上限2GB，审计归档上限5GB；磁盘低于10%或2GB触发WARN。容量不足停止归档清理并记录状态，不先删除未归档审计、不阻止业务读取。关键写入无法写outbox时按上述事务规则拒绝。首次实施不批量清理历史，先展示预计过期数量和配置；用户审查同意默认值后启用定时策略。没有短信邮件或站外告警。

## 7. 验收与实施顺序

先批准设计，再实施：迁移和权限范围→统一traceId与脱敏→操作事件与outbox→运行采集与登录事件→四个管理页面→保留/清理→真实验证与说明。优先补齐关键写入，逐模块覆盖，不重复搭建两套权限与日志平台。

验收必须覆盖：

1. 新增/编辑/审核/领料/产出/结算/冲销/预警处理成功和失败均能关联到业务单号、操作人、工厂和traceId；事务回滚只有失败记录。
2. 普通人员无法越权查看；本厂管理员对列表、详情、导出、直接旧接口请求均只能本厂。未归属旧日志与全局共享日志仅超级管理员。
3. 验证错误、权限拒绝、HTTP200业务拒绝不会漏记或误判成功；UUID重复仅一个过账事件。
4. 嵌套密码、响应token、SQL凭据、上传文件和异常消息哨兵不进入DB/文件/导出；手机号遮罩有效。
5. 并发请求不串traceId，异步任务仍关联原请求；前端错误可复制追踪ID。
6. WARN能落盘，异常有脱敏根因与栈；日志DB不可用时文件可定位，回补去重；请求不得无限等待日志队列。
7. 重启恢复outbox与文件游标；归档失败不删除；任务并发不重复清理；缺失日期能补执行。
8. 页面筛选、详情、权限、导出上限、配置版本冲突正常；复制技术信息不包含会话。
9. 日志模块不能改库存、工单、损耗等业务事实；不改变原本失败请求的错误语义。

测试包含JUnit脱敏/结果分类/工厂范围与清理边界，独立工厂真实接口覆盖和浏览器操作。系统连接失败/队列/磁盘故障采用独立测试配置模拟，不停用用户正在使用的数据库或Redis。测试记录明确区分模拟故障和真实运行结果。

## 8. 用户故障定位手册

用户遇到失败：记录页面、业务单号、操作时间和追踪ID；不要反复提交未知结果的非幂等操作。管理员按追踪ID查看操作结果→业务规则拒绝核对前道数量/库存/引用→SYSTEM_ERROR查看运行详情与根因→按对应流水确认事务是否提交。服务无法访问时先查5173/8080监听、MySQL/Redis服务、启动日志，不能只依赖系统内页面。导出日志使用上述脱敏和范围限制。

设计默认值为建议配置，本轮没有开启定时删除，也没有给人员新增日志权限。用户于2026-10-14批准实施，实际使用与验收见日志管理使用与验收说明。
