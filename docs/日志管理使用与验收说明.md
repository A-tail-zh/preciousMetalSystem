# 日志管理使用与验收说明

实施日期：2026-10-14，数据库迁移V17。

## 如何查看

超级管理员登录后，在侧栏“系统管理”打开操作日志、登录日志、系统运行日志、日志配置。列表默认16条。操作日志默认最近7天，最长31天；运行日志默认24小时，最长7天。支持追踪ID、人员、模块、业务单号和结果等筛选。

普通工厂人员不会自动获日志权限。通过角色管理授予 monitor:operlog:list、monitor:operlog:query，可查看其当前工厂的单厂日志；导出另需 monitor:operlog:export。登录、运行、配置除权限外还强制要求超级管理员。旧日志没有历史归属，仅超级管理员查看。跨厂迁移事件不向普通账号展示。

## 故障定位

操作失败时，错误响应返回traceId，界面提供复制追踪ID通知。每个响应也包含X-Trace-Id。复制后在操作日志和系统运行日志筛选同一个ID，查看失败原因、前后数据库快照和技术栈。库存事实仍以库存流水为准。

密码、验证码、令牌、Cookie及Authorization按字段递归脱敏；手机号遮罩。日志用纯文本显示，无取消脱敏开关。长请求/响应和变更标记截断。仓储文件导入记录元数据及SHA-256，不保存文件正文。

## 事务与恢复

关键业务事务内写audit_outbox，写入失败会抛错并回滚业务。提交后每秒按eventId投递，失败按1/5/30/120/600秒重试。普通读取不产生逐次业务审计；敏感人员/角色详情及日志详情另记录访问事件。UUID重放标记replayed，不再过账。

失败审计及登录入库失败时写logs/audit-fallback.jsonl，数据库恢复后依据文件游标回补。运行日志主文件logs/runtime.jsonl，INFO/WARN/ERROR统一落盘，ERROR及登录另有独立JSON文件。按50MB和日期滚动、gzip归档；运行采集器按文件游标和eventId去重。

自动归档清理默认关闭。配置版本冲突拒绝覆盖。启用后上海时间02:30之后执行并补查遗漏日期，锁定配置行避免并发重复。操作与登录日志先gzip归档，校验SHA-256和内容后按1000条删除，失败不删除；每轮限制20批避免长时间占用。运行数据库日志直接按保留周期分批删除。低于2GB或10%空闲空间停止归档，审计归档容量上限5GB。归档超期文件只根据受控清单及哈希校验清理。待投递outbox不按时间删除，已投递保留7天。

## 验证

- Maven全模块构建及业务既有测试，新增日志脱敏、outbox异常传播、归档失败不删除单元测试。
- tools/verify-audit-live.mjs：真实事务成功记录、工厂隔离、旧日志保护、超级管理员限制、清空禁用、失败响应追踪、配置冲突及查询边界、关联运行WARN。
- frontend/tests/audit-live.spec.ts：四页面直接访问、刷新、导航高亮及详情。
- 故障测试使用mock，不中断用户正在使用的数据库或Redis。

## 使用边界

日志文件与数据库均为本机管理存储，不宣称不可篡改。运行日志采集是异步的，页面可能延迟几秒；数据库完全不可用时从服务器logs目录定位。当前运行文件容量1GB，ERROR及登录各512MB，合计2GB。首次实施没有清理历史记录，没有自动给现有演示角色授权。
