# 候选接口权限与仓储单据初始化修复及验收

日期：2026-10-19。范围：候选接口权限、仓储单据初始化竞态及直接关联的保存/导入生命周期。不提交或推送 GitHub。

## 一、原因和影响

### 候选接口权限过宽
控制器将仓库、库存、单据、批次、预警的列表权限合并为 OR；服务层按 kind 执行 SQL，未再次鉴权。候选端点因此成了读取受限数据的旁路。原复现账号只有 `metal:warehouse:list`，直接查询库存和单据得到403，但候选接口仍返回同厂库存97g、客户及出库明细3g。工厂隔离原本仍生效，此次并非跨厂穿透。

最终复核还确认：`out-lines` 包含明细重量和客户，单据列表权限不足以授权明细。最终矩阵仅允许单据详情、添加或导入权限读取这一候选。

### 初始化响应覆盖
原 `open()` 在多个 await 之间直接写入共享 form，最后无条件 `visible=true`。已有 optionEpoch 只保护工厂依赖加载，没有覆盖编号预留、初始工厂请求、最终弹窗打开。旧 OUT 初始化可以在新 IN 表单取消后返回，把旧编号写入并重新打开弹窗。

## 二、详细解决方案与实现

### 1. 按候选种类鉴权
`WarehouseService.permitOption(kind)` 在 SQL 与工厂数据访问前检查权限；控制器要求认证，具体授权集中由服务层实施。未知种类直接拒绝，管理员也不能读取未知资源。通配权限使用系统统一匹配函数。

| 候选 | 允许的业务权限 |
|---|---|
| factories | 仓库查看/详情/新增/编辑，库存查看/详情/新增/调整，单据查看/详情/新增/导入，批次查看/详情/新增，预警规则查看/新增/编辑、预警记录查看/详情 |
| warehouses | 库存查看/详情/新增；单据新增/导入 |
| people | 库存新增/调整；单据新增/导入 |
| materials | 库存新增；单据新增/导入 |
| products | 库存新增；单据新增/导入；预警规则新增/编辑 |
| processes | 预警规则新增/编辑 |
| work-orders | 批次新增；单据新增/导入 |
| batches | 批次查看/详情/新增；单据新增/导入 |
| stocks | 库存查看/详情/调整；单据新增/导入 |
| out-lines | 单据详情/新增/导入，排除仅列表查看 |

这里的候选授权不授予保存、调整或冲销操作权限；操作接口仍有各自检查。工厂范围继续由 FactoryScope 执行，不修改角色、菜单或业务数据库结构。

期初库存初始化只请求工厂、仓库、人员、物料、产品五类基础候选，不请求无关的库存、生产工单、批次、出库来源。单据新增可以获得业务录入必要的候选，不额外要求库存列表权限。调整所需人员候选保留；调整页面本来仍依赖库存详情权限，本次没有扩大详情授权。

### 2. 整次打开使用独立上下文
每次打开生成独立的 epoch、单据类型、期初标志、产品类别和UUID。编号、工厂及依赖先加载到局部变量，仅仍是最新上下文时才一次性发布表单、选项和弹窗可见状态。

以下操作使旧上下文失效：新打开、取消加载、关闭弹窗、父页标签切换和组件卸载。旧成功/失败/finally 不再改变最新初始化状态。加载时提供取消入口；最新失败保持弹窗关闭，显示重试。

重试沿用同一UUID；新打开使用新UUID。回归发现快速重试会被全局1秒防重拦截，因此仅为编号预留请求设置 `repeatSubmit:false`，依然由服务端UUID、申请人和类别保证幂等；保存接口的防重不变。

### 3. 关联异步与保存保护
工厂依赖、库存复查和导入增加生命周期检查，旧导入不能追加到新单据；移除未使用且缺乏保护的批次重载函数。保留既有工单和批次详情请求保护。

保存数据在请求前深拷贝，保存中拒绝重开，父页禁止切换标签，取消和关闭入口禁用。卸载后的保存响应不再提示成功或触发 saved 刷新。
