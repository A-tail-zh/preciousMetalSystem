# 全系统输入校验统一修改与验收

## 本轮变更

- 输入字段清单：扫描现有表单和请求类型，并核对实际数据库650列元数据，保存在同目录 input-validation-inventory 报告及运行证据中。
- 公共接口：保留URL、请求主体与 code/msg；参数错误增加 fieldErrors（field/code/message）。提供嵌套行路径、中文提示，避免返回Java类型、SQL及异常堆栈。
- 严格数值：在Jackson绑定前检查原始数字token，拒绝科学计数法、分数件数、整数溢出、非法日期、隐式空原始类型及数字布尔值；不改写请求字节和幂等指纹。
- 基础资料：补齐已有容量、类型和精度校验；产品尺寸新建或修改执行新格式，未修改历史格式由后端加载原记录比较并兼容，数值安全始终检查。
- 工单与跳步：产品数量、产品选择及工序起止时间定位到字段；跳步来源/目标有效性、原因和UUID校验，路线不足三步禁止新增。
- 仓储与还料：单据头、物料行、实际完成数量、库存调整及全部还料确认提供字段提示；保留库存、来源、权限、额度、结算和冲销规则。
- 报价及系统管理：报价精度沿用基础价6位、π15位；系统字段按各自表容量校验（公告备注255，参数等备注500），下拉枚举在后端检查；查询仍可空。
- 表现：已有规则的表单提交时定位首个错误，错误文本换行；关闭重开和来源改变清理数量原始输入，保留失败草稿。

## 代码审查与修复

独立审查发现并处理：

1. JSON数字解析先归一化，导致部分科学计数法绕过：改为保留原始token，并覆盖1e0、1e-1、1.0e-2等。
2. 分组还料/单商品报价错误路径不匹配页面：补分组索引及商品索引映射。
3. 库存调整和还料类型切换残留数量缓存：切换/重开时清理。
4. 报价规则校验等待期间权限变化：提交前复核，加载与保存增加请求隔离。
5. 系统备注缺少容量校验：按真实表容量分别补齐，新增边界测试。

额外自查修复了件数输入使用v-model.number时把“1e0”提前转换为“1”的问题：现在保留原始字符串，校验通过后再转换提交。补充null原始类型及数字布尔值拒绝测试，并统一必填标记。

旧仓储一百万件限制属于此前实现，本轮未修改该后端规则。
