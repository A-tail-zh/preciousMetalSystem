# 库存调整与工单详情回显复现

本轮仅创建隔离测试数据并测试，未修改业务逻辑，未提交GitHub。

两组数据均按新批次流程完成领料、半成品入库、无余料确认结算；第一组计划33件、首工序实际完成1件，库存1件/100g；第二组为重量工序，产出100g、参考件数1。

| 场景 | 实测结果 |
|---|---|
| 在仓库页面填写数量差额+32并提交 | 实物库存正确变成33 |
| 查看原来已打开的工单页 | 库存仍显示旧值1，没有跨页面自动更新 |
| 点击半成品流转区域刷新 | 剩余库存显示33；本单加工仍为历史1件 |
| 整页重新打开 | 剩余库存显示33 |
| 重量库存参考件数调整为33 | 接口返回referenceQuantity=33，净重仍100g |
| 重量工序详情 | 本单加工100g；实物件数显示—；表格没有参考件数列，33不会展示 |
| 产品配置后来改重量模式 | 已有按件工单快照仍保持按件 |

结论：历史加工数量不随库存调整变化属于正确口径；已打开页缺少自动刷新、重量库存参考件数缺少展示，是两处确实存在的显示问题，均未在本轮修改。

共10项业务与页面核对，另验证清理后无有效测试工厂。测试业务数据按既有fixture清理，工厂按系统软删除规则处理，审计日志保留。

证据：.runtime/adjustment-detail-display/result.json、run.log、piece-after-refresh.png、weight-after-adjust.png。可复用脚本tools/verify-adjustment-detail-display-live.mjs。
