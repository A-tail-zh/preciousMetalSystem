# 四项隐藏缺陷调整计划

> 实施方式：使用 executing-plans 按任务执行，先复现失败，再修复并验证。现有工作区改动必须保留，不自动提交或推送GitHub。

**目标：** 修复库存调整错目标、外部客户库存混合、旧角色撤权未失效、日志详情竞态四项已复现缺陷。

**技术：** Vue 3 / TypeScript / Element Plus；Spring Boot / Spring事务 / MySQL / Redis。

**依据：** `.runtime/hidden-review/results.json` 与各项浏览器及真实接口复现证据。

## 1. 库存调整固定目标（P1）

- 为库存调整建立独立目标快照，包含库存ID、版本、分类、工厂、仓库、编码、品名、规格和单位名称；不得再使用其他详情窗口共享的detail作为提交目标。
- 工具栏、行操作和库存详情内“调整库存”统一进入同一个打开流程。请求代次覆盖库存详情及人员选项两个异步阶段，只有最新请求能打开或更新调整窗。
- 调整窗口显示只读目标信息。毛重/杂质显示规则、净重计算及POST目标均使用此快照。
- 加载时禁止确认，失败清空目标并提示重新打开；关闭、切换库存标签、刷新列表及卸载使未完成打开请求失效。
- 保存时捕获目标与负载，禁止重复提交、关闭及切换目标，失败保留输入以便重试；服务端版本冲突要求重新加载，保留原有权限和余额校验。
- 接口及数据库不变。

## 2. 外部半成品/成品不同客户禁止合并（P2）

- 本轮采用最小兼容方案：同厂、同仓、同产品、同分类、同批号已有库存时，必须同客户且同生产来源才能合并；不同客户明确拒绝，提示更换批次号或核对客户。
- 客户名称沿用去除首尾空格的规则，不进行大小写折叠、简称推断；空名称与非空名称视为不同客户，两者都空沿用现有规则。
- 客户使用所属客户字段organization，不使用收货单位receivingOrganization；不改写已有库存客户以迎合新入库。
- 单据保存和导入预览共用校验；导入多行之间也检查同键不同客户，保存时在锁定库存后再次检查，防止绕过预览或并发合并。
- 保留同一生产批次来源校验、库存余额及重量规则；原料的现有单位隔离保持。
- 不修改唯一键、不新增数据库字段、不自动生成替代批号。
- 只读重查历史客户不一致库存，包含空客户；列入人工处理清单，不自动拆分、补写或重算历史余额。

## 3. 旧角色授权/撤权同步失效会话（P2）

- 覆盖旧接口单人撤权deleteAuthUser、批量撤权deleteAuthUsers及批量授权insertAuthUsers，参数分别提取目标人员，不能把roleId当作userId。
- 使用事务包裹该授权变更及目标人员auth_version增加；变更前锁定并确定实际受影响人员，批量去重，空/非法参数明确拒绝。
- 复用FactoryScope.invalidate：认证版本在同一数据库事务中更新，Redis会话在提交后清理。失败回滚不撤销原会话；Redis清理异常时旧令牌仍因版本不同被拒绝。
- 保持旧接口超级管理员限制，授权沿用角色有效性、工厂范围和禁止给普通账号分配超级管理员角色的现有规则。
- 重新登录按最新角色获取权限，不修改8小时有效期及自动续期。
- 不改接口路径或请求结构，不批量清空无关账号会话，不修改历史授权。

## 4. 日志详情仅接收最新响应（P2）

- 操作日志、运行日志详情增加独立请求序号、目标ID和加载状态；与列表查询序号分开。
- 点击时清空旧详情并显示加载，只有最新请求能写入当前内容、追踪ID及打开状态。
- 旧失败不能清空新详情或改变新请求加载状态；最新失败清空内容并提示重试。
- 关闭弹窗、查询/重置/翻页以及卸载时使未完成详情失效，不让迟到响应重新打开窗口。
- 加载中禁止复制追踪ID；复制只使用当前成功详情。
- 不改变日志查询、导出和权限接口，登录日志不新增详情入口。
