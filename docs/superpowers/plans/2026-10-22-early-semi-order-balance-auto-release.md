# 更早工序半成品领用、整单重量总账与自动释放实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在明确工艺许可下支持本工单更早工序半成品直接领至后续工序，建立不重复计算内部流转的整单重量总账，并让符合条件的新工单在正常完成后自动释放剩余半成品。

**Architecture:** 共用来源政策与数量覆盖规则，批次保留真实加工和许可跳步快照；重量总账独立只读聚合单据、库存和有效报工。正常完成事务写入持久化释放事件，事件处理器复用释放核心、锁和幂等账，不通过增加实物库存实现释放。

**Tech Stack:** Spring Boot / JdbcTemplate / MySQL / Flyway；Vue 3 / TypeScript / Element Plus；JUnit / Mockito / Playwright / Chrome。

**Spec:** 本文件第一节记录的用户确认及业务边界，是本计划的业务依据；本轮仅编写计划，未授权执行迁移、修改代码或业务数据。

## 一、用户已确认的口径与实施边界

用户明确选择：
1. 本工单更早工序的半成品，允许直接进入后续工序，但必须配置明确的工艺跳步许可。例如工序一的半成品可按“工序一→工序三”许可直接投入工序三。
2. 仅正常完成的新工单自动释放；部分关闭及历史工单单独确认。

本计划采用以下具体实现边界：
- 跳步许可不是补造工序二的报工。工序二显示“许可跳过”数量，实际加工和实际损耗仍为0。
- 新增跳步领用仅限本工单、同一产品明细。不同产品明细、不同工厂、不同产品/规格不互相替代。
- 第一工序仍从原料开始；允许后续工序补充原料，但补料不增加可完成件数。
- 一批次一条加工轨迹：可领多个批次/多种原料，但半成品的已加工/已跳过步骤组合必须相同。上一道正常半成品与跳步半成品的轨迹不同，应分批登记，不能混成无法区分来源的产出。
- 保留当前“每个产品明细/工序只允许一个未结算批次”的入口规则。轨迹不同时提示先结算或冲销当前批次，再建立另一批次，不静默拆单。
- 跨工单仍按原完整前置路线要求。带有跳步轨迹的半成品，不因完成或自动释放而被当作完整加工路线；第一版列为“跨单路线不适用，未自动释放”。若后续需要跨单承接跳步轨迹，应另行设计目标工单的接收许可。
- “新工单”由服务器创建时写入资格标记，不根据完成时间猜测。上线前已有工单默认无自动释放资格；本期不自动回填。
- “消耗”在重量等式中指加工损耗，不等于所有领料重量。

## Global Constraints

- 不修改历史库存、单据、报工和损耗归属，不自动补领料、补加工或关闭旧工单。
- 第一工序原料领用、原料多行还库、半成品还库和成品销售规则保留；还库单仍来自同一生产出库单。
- 商品规格只规范化首尾空白；按产品ID及保存路线快照匹配，不用名称推断等价。
- 重量全部使用BigDecimal与6位小数十进制字符串；数量使用整数，ID按字符串返回。
- 仓储候选接口保持最小权限和工厂隔离，不依赖完整产品/工序/工单管理查看权限。
- 保存和导入继续执行后端权威校验；前端候选、额度及许可展示不是授权依据。
- 新可选字段不改变旧请求的幂等指纹；同UUID不同内容拒绝，旧请求重放兼容。
- 复用工厂锁；写入按工厂→工单→批次→按ID排序的库存→按ID排序的释放记录固定顺序加锁。
- 不恢复此前隐藏的消耗总表入口或旧报工查看入口；在现有工单详情增加独立重量总账区域。
- 新权限不自动授予现有角色；本轮及后续实施均不自动提交或推送GitHub。

## 二、本工单更早工序领用与工艺跳步许可

### 2.1 许可配置

新增“工艺跳步许可”配置，权限为 `metal:route-skip:configure`，普通仓储录入人员只能使用已配置许可。

许可明确绑定：工厂、产品ID、规格快照指纹、完整路线指纹、来源工序ID与顺序、目标工序ID与顺序、因此跳过的工序列表、启用状态、版本、配置人、原因。

- 来源顺序至少为1，目标顺序必须大于来源顺序+1；紧邻领用仍走原规则。
- 工序一→工序三许可不自动授予工序一→工序四许可。
- 保存配置时校验跳过列表正好等于源、目标之间的步骤；名称仅显示，不能代替ID。
- 配置修改生成不可变版本记录。新增领用必须使用当前启用版本；停用不改写已经过账的领用，原领用的还库及受控冲销仍可执行。
- 该权限按工厂检查；配置界面使用专用最小上下文，不借此暴露其他工厂产品及路线信息。

### 2.2 候选与填写

生产出库候选顺序：原料→本工单上一道半成品→本工单更早工序且具有许可的半成品→其他工单已释放且完整路线匹配的半成品。

更早来源显示：已完成工序、来源批次、可领件数/净重、跳步许可编号/版本、将跳过的工序。添加明细前明确确认“按该许可跳过……”。

没有许可、许可停用、规格/路线变化、来源未结算或待核对、缺少真实来源、跨产品明细的库存不得通过保存、导入或旧接口绕过。

候选返回 `sourceMode`、`routeProfileHash`、`routePermitId`、`routePermitVersion`、`newlySkippedSteps` 和逐工序共享额度。请求中只接受必要的许可ID/版本；源路线、跳过步骤及余额由服务器重算。

### 2.3 数量覆盖与真实轨迹

每道步骤校验：

**本单已结算加工数量＋未结算批次计划预占＋外部接入覆盖数量＋本单许可跳过数量≤该产品明细计划数量。**

- 许可跳过数量来自有效跳步生产出库件数，减去对应半成品还库件数。
- 只给本次真正跨过的步骤记覆盖；后续正常领用同一半成品时，继承轨迹但不再次增加跳过数量。
- 实际产出和结算完成件数仍不得超过净领用半成品件数或批次计划。
- 所有来源共享涉及步骤的剩余额度，不为每条库存重复分配完整额度；导入与本单待提交明细共同计算。
- 轨迹不同的半成品不能并入同一生产批次，原料补充不影响轨迹判定。
- 来源批次记录真实已加工步骤、历史许可跳过步骤及本次新增跳过步骤；后续查询不得仅凭“第3道已结算”推断第2道实际加工过。

例：计划10件，第一步加工10件；第二步实际加工6件，另4件依据1→3许可直接领到第三步。第二步显示本单加工6、许可跳过4、覆盖10；第三步实际加工10件。第二步仅6件对应真实报工，不生成另外4件的假报工。

正常完成要求：各步骤合法覆盖计划数量，最终步骤实际结算完成计划数量，无未结算批次。最后一道不能仅靠跳过覆盖完成。

### 2.4 还库、停用与冲销

跳步领用的未加工半成品仍通过SEMI_RETURN恢复原库存，不创建新产出；同步减少本次新增跳过覆盖。保存后重新检查有效产出件数。

已被下游领用的产出不能先冲销其上游；批次整体冲销同事务恢复库存、释放额度、外部接入与跳过覆盖。不删除许可快照，不因许可停用阻断合法退回原来源。

## 三、整单重量总账

### 3.1 账的边界

重量账覆盖一张生产工单全部产品明细，可展开产品→工序/批次→单据/物料。不把件数与克数相加。

基础公式只在全部结算、无跨单转出、无特殊库存调整时简化为：

**原料领入＋外部半成品领入＝成品累计产出＋本单半成品在库＋已结算损耗＋原料还库＋外部半成品还库。**

完整公式为：

**原料领入＋外部半成品领入＋本单来源半成品库存净调整**

**＝成品累计产出＋本单半成品在库＋半成品跨单净转出＋其他半成品净出库＋已结算损耗＋原料还库＋外部半成品还库＋未结算在制差额＋核对差额。**

`核对差额`单独显示，正常数据应为0，不能把它自动写为损耗或补库存。

### 3.2 各项定义

| 项目 | 口径 |
|---|---|
| 原料领入 | 本工单有效PRODUCTION_OUT的RAW净重，包含各步骤补料 |
| 外部半成品领入 | 领入库存原来源工单不同于本工单的SEMI有效生产出库；还库单独列出，不把原始领入记录抹掉 |
| 本单内部半成品流转 | 单独追溯显示，不计入新增投入，也不重复计作最终去向 |
| 成品累计产出 | 本工单有效FINISHED_IN净重；以后销售出库不减少生产累计产出 |
| 本单半成品在库 | originBatch对应本工单的半成品当前实物余额，按来源库存逐条计算 |
| 半成品跨单净转出 | 本工单产出的半成品被其他工单有效领用，减去对应半成品还库 |
| 其他半成品净出库 | 本单来源半成品的有效非生产出库，单独列明单据，不伪装成损耗 |
| 本单来源半成品库存净调整 | 仅本单来源半成品的合法库存调整，保留正负号；原材料公共库存调整、成品销售后调整不套入本单生产账 |
| 已结算损耗 | 有效已结算报工损耗之和，独立取值并与有效单据核对，不用整单残差倒算 |
| 原料还库 | 本工单有效RAW_RETURN |
| 外部半成品还库 | 原出库属于外部半成品的有效SEMI_RETURN；本单半成品还库属于内部流转，不重复计出去向 |
| 未结算在制差额 | OPEN批次领料－原料还库－半成品还库－半成品/成品产出，标明“尚未结算，含待确认损耗”，不称为已称量在制实物 |

释放仅改变使用资格，不计入以上增减重量。库存恢复及冲销按有效单据/有效账务变化净额处理，不能同时统计VOID原单和冲销流水。

### 3.3 手工验算样例

A原料领300g、还100g、损耗20g、成品140g、半成品在库40g：300＝100＋20＋140＋40。

A释放40g：数值不变。

B领走其中20g：A账为300＝100＋20＋140＋20在库＋20跨单净转出；B账新增外部投入20g。

B产出18g、损耗2g：B为20＝18＋2；A历史损耗仍为20g。

如B将未加工部分还给A：B显示外部半成品还库，A在库恢复、跨单净转出减少；不得新记一次释放或再次记原加工损耗。

### 3.4 界面与异常

工单详情新增“整单重量总账”，默认本工单全部产品；可按产品明细查看。展示投入、去向、已结算损耗、未结算差额、核对差额、读取时间和核对状态。

同一只读事务产生汇总和snapshotToken。令牌依据参与计算的工单/批次/报工状态、来源库存版本及相关流水生成；其他工单领用本单半成品也必须使它失效，不能只看原工单version。分页、展开及导出重检令牌，变化时返回需刷新，不拼接新旧数据。导出自身在一个只读事务中生成一致的数据。首次不提供任意历史时点查询，避免用当前库存冒充历史余额。

历史缺来源、报工与单据不一致、负数或件重异常显示待核对及具体单号；不把未知归属填成0，不猜测跨单关系，不修改历史数据。缺少必要依据时显示“不完整，不能确认平衡”。

## 四、正常完成后自动释放

### 4.1 资格和触发

新增工单服务器字段 `auto_semi_release_eligible`，数据库默认false。功能启用后新建工单由服务端置true；已有工单不自动回填，客户端不能指定此值。

仅在有资格工单真实从未完成转为COMPLETED时，递增 `completion_generation` 并在同一事务插入唯一自动释放事件。批次结算本身、部分关闭、重复刷新、查询工单均不触发。

新工单部分关闭后仍走手动释放。历史工单仍走现有手动释放。

### 4.2 持久化事件与释放额度

事件唯一键为工单ID＋完成代次。处理器由提交后触发，并由持久化定时扫描补偿，防止进程重启丢失事件。

处理事务重新锁定工厂、工单、来源库存和释放记录，确认当前仍正常完成且代次一致，再计算：

**本次可自动释放＝真实库存余额－已有释放但尚未领用的额度。**

- 只处理本工单产生、已结算、来源正常、规格与完整路线可验证的半成品。
- 每条库存的剩余件数和净重一起释放；两者均0则无动作，仅一项为0或负数则待核对。
- 带跳步轨迹的来源按第一节边界列为跨单不适用，不冒充完整路线自动释放。
- 自动释放记录标记AUTO、完成事件、库存ID、发起完成操作的人员、系统执行原因；保留原工单、产品明细、批次和路线。
- 不生成出入库流水，不增加实物库存；手动释放并发时锁内重算，不能重复释放。
- 自动记录唯一关联事件＋库存；重复执行、重启重放和同UUID请求均不重复建账。

### 4.3 权限、异常和重试

自动释放是已启用业务策略下的系统动作，复用无权限绕过的内部释放核心；完成操作本身仍须原有结算权限。不要求每名结算人员再持有手动释放权限，也不授予其手动释放/撤销权限。

手动释放和撤销继续要求现有独立权限。自动任务不能调用公开接口伪装管理员，也不能关闭工厂隔离。

- 技术失败：当前处理事务整体回滚，事件按2、10、30、120、300秒重试，首次失败后最多重试5次，第五次重试仍失败转失败并展示原因；不回滚已提交的真实生产结算。
- 来源业务不适用：记录库存、原因和状态；合法库存可释放，异常库存不释放，事件显示部分完成/待核对。
- 工单已被撤回或完成代次失效：事件取消，不释放。
- 自动记录被人工撤销后，同一事件不再次生成；只有新的合法完成代次或明确的受控人工操作才能再释放。
- 若要冲销导致已完成工单重新打开，应检查整张工单的有效释放和跨单依赖，不能只检查当前来源批次。列出阻断单号，先撤销未使用释放、处理下游引用，再执行冲销。

界面显示“无需释放／待处理／已自动释放／部分完成／待核对／失败”，并展示件数净重、来源及具体原因，不把COMPLETED误显示为自动释放已成功。

### 职责划分

新建后端服务：
- SemiSourcePolicyService：decide(stock,target,permitId,permitVersion) -> SourceDecision；统一DIRECT、OWN_EARLIER_PERMITTED及拒绝原因，维护真实路线。
- ProcessCoverageService：snapshot(itemId) -> CoverageSnapshot；validate(itemId,pendingEffects)；统一加工、预占、外部接入和本单跳过额度。
- WorkOrderWeightBalanceService：summary(workId,itemId)、lines(workId,itemId,category,page,size)、export；全程只读，不倒算/改写生产损耗。
- SemiReleaseCore：提取同事务额度及记录写入；手动服务保留权限检查，系统任务使用经验证的完成事件上下文。
- WorkOrderCompletionService：统一完成判定、代次与事件登记，供结算和冲销调用。

## 七、核心验收矩阵

| 场景 | 预期 |
|---|---|
| 无许可将一步半成品投入三步 | 候选不放行，导入/保存拒绝 |
| 有效1→3许可领4件 | 三步实际领料4；二步许可跳过4，不产生二步报工 |
| 二步实际6＋许可跳过4，计划10 | 覆盖10，未超计划 |
| 二步实际6＋许可跳过5 | 拒绝；无扣库、无虚假覆盖 |
| 三步半成品再领到四步 | 继承真实轨迹，二步跳过不再加4 |
| 上一道与更早来源轨迹不同 | 不允许混批；提示分批，不静默合并 |
| 跳步领4，还1，产3 | 原库存恢复1；新增跳过覆盖变3 |
| 许可停用后还原来源 | 允许合规还库；禁止新增跳步领用 |
| A300=成品140+半成品40+损耗20+还100 | 核对差额0 |
| A释放40 | 总账和库存不变 |
| B领A20再产18损耗2 | A计半成品转出20；B计新增投入20及自身损耗2 |
| 本单内部半成品多次流转 | 新增投入不重复累计 |
| 开放批次差额10 | 显示待结算差额10，不能称为已确认损耗 |
| 新工单正常完成 | 唯一事件，符合条件余量自动释放 |
| 旧工单完成或新工单部分关闭 | 不自动释放，保留手动入口 |
| 跳步轨迹剩余半成品 | 不伪装成完整路线自动释放/跨单使用，展示不适用原因 |
| 重启、重复投递、并发手动释放 | 不丢任务、不重复建账、不超放 |
| 有跨单引用时冲销完成工单 | 阻止，列出具体依赖 |
| 人工撤销自动记录后事件重放 | 不自动重建已撤销记录 |
| 跨厂、无权限、版本冲突 | 拒绝且整体回滚 |
