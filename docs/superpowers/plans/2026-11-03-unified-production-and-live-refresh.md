# 同工单全流程、跨用户刷新与历史酸洗入口实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. 按下列唯一文件归属并行，整合与共享构建由库存会话负责。

**Goal:** 一张产品工单从前处理原料到成品闭环追溯，业务页面跨用户自动更新，历史独立酸洗仍可查询而库存工具栏不再保留入口。

**Architecture:** 复用 PRODUCTION、现有 ProcessingPolicy 阶段、工序/批次/产出快照、双人交接、库存及质量总账，不另建平行生产体系。新增行为使用独立的新执行规则版本，旧工单快照和既有结果保持；跨用户采用可见页面默认5秒的合并轮询，编辑时只探测变化并保留草稿及原请求身份。

**Tech Stack:** Java21 / Spring / JdbcTemplate / MySQL / Redis / Vue3 / Element Plus / TypeScript / Playwright；不新增依赖。

**Spec:** 本文件“已批准需求”及用户通过“梳理工单与仓库”会话于2026-11-03明确转交的增量要求；原业务基线见 `docs/项目业务与开发对接文档-2026-11-02.md`，运行现状以最新源码和本轮证据为准。

## Review Focus

1. 后续某批结算不等于前处理工序结束；有真实本单前处理时必须完成受控结束投产，资格承接不能伪造加工量。
2. 已结算的上游部分产出可向后分批领用，但同工单不同产品明细不得偷偷互替；跨客户/金属/工厂/路线或未结算来源一律拒绝。
3. 自动刷新不得覆盖称重/编辑/确认草稿；提交结果未知时保留原请求ID、内容与恢复状态，不能用新的版本号静默重提。
4. 迟到响应、finally、跨账号及撤权不能串数据；轮询失败保留旧值并退避，不能5秒反复全局弹错。
5. 历史无工单酸洗仍有可达入口且原授权可查；不能为了搬入口开放新建工单或独立新酸洗权限。

## 已批准需求与验收口径

### A 同号完整生产工单

- 常规建单以最终产品及完整路线为核心，默认PRODUCTION，不要求把“产品生产/原料加工”作为互斥必选题。保留独立纯原料业务与历史记录兼容入口。
- 建单确定工厂、客户、产线、负责人、加工形式、日期，可多最终产品，各自保存产品/规格/金属/计划件数及完整路线快照；实际仓库、库存和领量在出库确定。不新增开工后补产品/替换路线能力。
- 前处理RAW，融定及后续中间SEMI，末道FINISHED；不强制所有产品酸洗，不凭名称猜类型，不用当前配置解释历史。
- 库管申请出库及预占→指定加工人员逐行实领→加工人申报主产出及全部余料/无余料→仓管复称→全部仓库原子入账并结算→下一工序领用。
- RAW/SEMI产出形成新的具体库存，保留工单/产品明细/工序/批次/来源；不原地将旧库存改类别。混料保留实际投入来源，不猜逐克比例。
- 分批可并行衔接，不要求整道上游先结束；未验收或未结算产出不可用。外部合格原料/半成品、厂料自补、既有受控跳步保留，但资格与本单真实加工分别展示。
- 内转不重复算新增投入，重量与件数、参考件数及加工历史各自独立。阶段损耗不能直接相加；加工称重决定损耗，库管实收决定库存，差异单列。
- 工单按产品展示前处理/融定/后加工/成品进度、批次和相关单据，原料及半成品库存可反查工单和下游。整单完成需完整路线满足、重量工序结束投产且有效结算、无待实领/待验收/未结算；余料收尾与生产完工分别显示。
- 全路线真实隔离验收：同一编号建单→前处理实领交接→RAW→同单融定→SEMI→后加工→FINISHED→完工与余料收尾；至少证明内转、损耗、双方重量、差异与余额闭合，覆盖分批、多仓、厂补、重试/并发/权限/冲销及历史。

### B 跨用户刷新

- 默认可见页面每5秒检查/拉新，focus/visibility返回立即补查；同浏览器现有失效通知保留。覆盖工单、库存、单据/交接及相关资料列表/候选，不承诺毫秒实时。
- 刷数据区域，保留筛选/排序/分页和仍有效勾选；隐藏停止、卸载清定时器、避免重叠请求和每个子组件重复全量轮询。
- 失败保留旧数据，显示可能过期/更新失败并退避，无周期弹窗刷屏。后台读取有明确quiet选项，401仍按身份状态处理。
- 编辑/称重/确认只探测变化，明确过期及重新核对要求，不回填新版本后沿用旧草稿直接提交。余额变化须重新校验，不改实领值。
- 提交中、结果未知、同请求恢复独立于读取轮次；刷新不重置请求身份。按真实权限/工厂请求并阻止旧账号响应/finally。
- 两个独立登录浏览器上下文使用真实隔离接口验证静置自动更新、后台恢复、草稿不覆盖、并发确认、断网恢复/权限变化/重试，不以storage或mock替代真实证据。

### C 历史酸洗

- 移除库存工具栏按钮，在工单管理提供历史入口，保留旧无工单批次的列表/详情/原库存和单据/必要续办及受控冲销。
- 沿用原仓储查询/新增读取权限和工厂范围；无工单创建权限仍能查。不为缺工单菜单用户扩大业务权限，应提供只读历史路由或授权可达菜单适配。
- 新酸洗从完整产品工单路线查看，更新文案；独立新建继续禁止。保留库存反查，不硬挂旧批次到伪造工单。
