# 加工余料按原材料还库：设计与实施计划

> **实施要求：** 经用户确认后，使用 `superpowers:executing-plans` 逐项执行；每项先补失败回归，再实现和复核。本计划已完成实施与验收；保留用户现有业务记录，不提交或推送GitHub。

**Goal:** 支持半成品加工后剩余的粉末、边角料按实际选定的原材料入库，并正确扣减当前批次损耗，保留来源、客户、冲销及整单重量平衡。

**Architecture:** 新增仓储还库类型 `PROCESS_RAW_RETURN`（加工余料还库），归类RET、库存分类RAW、库存变化方向为正。绑定加工批次，不冒用“退回原出库明细”的语义；复用仓储单据、流水、权限、UUID及事务机制，单独建立余料来源关系和可用性校验。普通原料还库、未加工半成品还库维持原规则。

**Tech Stack:** 现有Java/Spring/JdbcTemplate/MySQL、Vue3/Element Plus/TypeScript、JUnit及Playwright。

## 一、确认口径与现有原因

用户已确认：操作人手工选择回收原材料，例如铱粉、铱块；客户沿用当前生产工单，不由用户改写。

目前：

- `WarehouseService.postLine` 的原料还库从原出库行取得类别、原材料ID和原库存，不允许将SEMI来源变成RAW。
- 半成品还库恢复原库存件数及重量，并校验有效领用件数减产出件数。已加工件数不能再次还为未加工件数。
- `RawReturnAllowance`、结算、消耗查询和总账只识别现有还库类型；仅新增一个前端选项会少扣损耗或使总账不平。
- 普通 `RAW_IN` 虽能增加原料库存，但不会减少加工批次损耗，也不能表达余料来源，不作为替代操作。

方案比较：直接放宽RAW_RETURN会破坏原库存恢复和明细归属；使用普通RAW_IN会丢失生产平衡关系。推荐独立“加工余料还库”，并在界面明确其入库分类是原材料。

## 二、业务范围与示例

### 2.1 三种还库保持区分

| 入口 | 用途 | 库存与件数 |
|---|---|---|
| 原料还库 | 本工序领入但未耗用的原材料 | 恢复原RAW库存，数量为0 |
| 半成品还库 | 领入但尚未加工的完整半成品 | 恢复原SEMI库存、件数及适用的释放额度 |
| 加工余料还库（新增） | 加工后形成的可回收粉末、边角料 | 新增选定RAW库存，只登记重量，不恢复半成品件数或释放额度 |

本期仅开放存在有效半成品生产领料、已有有效半成品/成品产出的未结算批次。尚未加工的半成品继续走半成品还库；批次完全未加工则沿用批次冲销。本期不开放已结算报工直接追加还料、成品拆解或跨厂转移。

允许同一批次多次回收、多种原材料、多条明细。不同来源半成品混合加工时，按目标加工批次追溯，不虚构每一克来自哪条领料；详情可展开该批次所有有效领料、产出及还库单据。

### 2.2 当前工单示例

WO20261023000129第二道碎料：有效领用半成品1件990g，有效产出半成品1件980g，批次未结算。

- 回收铱粉8g：增加本厂、当前工单客户的原料库存8g，损耗为2g；已完成件数仍为1。
- 回收铱粉6g和铱块3g：合计回收9g，损耗1g。
- 实测回收10g：损耗0g，不强制保留正损耗。
- 回收10.000001g：拒绝，不改变库存或单据。
- 不填写回收：不能自动推定实际损耗；现场核对并结算后按差额记损耗。

## 三、重量与数量规则

统一批次有效单据计算：

```
I = 原材料领用净重 + 半成品领用净重
O = 半成品产出净重 + 成品产出净重
R = 原料还库净重
S = 未加工半成品还库净重
P = 加工余料还库净重

本次余料可登记上限 = max(0, I - O - R - S - P - 本单其他待提交余料净重)
净投入 = I - R - S - P
损耗 = 净投入 - O
```

1. 仅统计POSTED且批次有效的单据；冲销记录不重复计入。
2. 三类还库与产出共享同一批次重量额度；增加新类型时必须同步更新旧还库额度及产出/结算校验，防止不同入口各自超退。
3. 编辑排除当前行，删除立即恢复本单额度；多原材料、多来源出库、多次提交共享额度。
4. `PROCESS_RAW_RETURN`净重必填、大于0、最多6位小数，件数固定0；毛重和杂质均不填时仅按净重保存，填写任一项则两项齐全且毛重减杂质等于净重，二者非负。
5. 未加工半成品还库仍减少有效领用件数；加工余料还库不减少件数，不能扩大产出/实际完成数量。
6. 未结算时显示“待确认差额”；结算后才显示损耗，不根据差额自动生成回收单。
7. 原料明细不再受“来源行必须RAW”的条件限制，因为新类型关联的是批次、目的物料，不是原出库行退回。

## 四、页面与交互

在仓储工单→还库单→添加中增加“加工余料还库”。表单顺序：

1. 工厂、还库类型。
2. 生产工单、产品明细、工序、当前未结算批次；同一上下文存在多个旧开放批次时明确提示核对，不自行挑选。
3. 还库日期、接收原料仓库、经办人、仓管员、验收人/审核人（沿用当前必填规则）。允许选本厂启用仓库，不要求退到半成品原出库仓库。
4. 客户只读回显工单客户，空客户或来源归属异常不得提交。
5. 物料清单：原材料（可搜索）、原材料编号/规格回显、实测净重、可选毛重/杂质、用途/备注；支持多条、多种原材料。
6. 还库原因必填，1至500字；不得把自动分摊当作实际称重结果。

提示文案：

> 用于半成品加工后产生的可回收粉末、边角料，按原材料入库并扣减本批次损耗；不恢复半成品件数。原材料由人工确认，客户沿用生产工单。

顶部展示领料、产出、三类已还重量及剩余可登记上限，标注“重量平衡上限，实际以称重为准”。候选仅包含有有效半成品领料及有效产出的OPEN批次；额度为0时不可新选。已选批次额度变化应保留上下文并提示原因，不默默切换其他批次。

保留“本批次结算”选项和独立结算入口；勾选时明确包含加工余料已登记，实际完成数量仍等于产出明细件数之和。

工厂、工单、产品、工序或批次切换时清空失效清单，关闭明细窗口并使旧请求失效。加载和校验期间禁提交；保存锁定目标、版本及UUID；失败保留输入，版本冲突要求刷新。路由离开后旧确认不得发请求。

## 五、数据、接口和追溯

### 5.1 数据设计

- 复用 `metal_warehouse_order`，`type=PROCESS_RAW_RETURN`、`kind=RET`，绑定当前work_order/item/process/batch。
- 明细`category=RAW`，`reference_id`保存人工选定的有效原材料ID，`quantity=0`；编号/名称/规格保存当时快照；客户由后端从工单读取。
- `source_line_id`留空，不指向某条SEMI领料并假装原库存还原。客户端传入库存ID、来源出库行、释放ID、跳步许可一律拒绝。
- 新增迁移建立 `metal_process_raw_return_line`：`line_id`主键/外键、`batch_id`、`inventory_id`、来源上下文快照JSON；索引batch_id、inventory_id。所有业务身份从后端读取，快照不存多余人员隐私。
- 每笔回收明细生成独立RAW库存批号，沿用现有批号+客户的库存身份，不与普通原材料收货或其他回收明细合并。由后端生成并校验，不能由用户自填冒用。
- 关系表作为回收库存标识；普通入库、期初、调整等不能追加到该库存身份。避免其他库存补入后掩盖原回收库存被消耗的事实。
- 不把回收RAW的来源伪装成半成品 `origin_batch_id`；通过新关系明确关联加工来源，并同步接入候选、保存、导入和冲销校验。
- 新迁移按实施时最新版本顺延，先备份；不修改已发布迁移，不重写历史库存或单据。

### 5.2 接口

复用仓储保存、编号、详情、列表、导出及导入接口，增加类型支持；新增最小只读上下文：

```
GET /metal/warehouse/options/process-raw-return-context
  factoryId / workOrderId / itemId / processId / batchId
```

返回：来源上下文、批次状态/版本、客户、有效领料/产出/各类还库重量、剩余额度、不可选原因。重量为6位小数十进制字符串，ID字符串。使用仓储录入范围，不要求额外产品/工序管理查看权限。

前端提交`batchVersion`；与当前`autoBind`会替换版本的行为分开处理，新类型必须核对用户加载时的真实版本，不能先覆盖版本再校验。保存前在事务锁内重算并再次确认批次仍OPEN。

保存和导入预览共用 `ProcessRawReturnService` 的上下文、金额无关重量、目的原料及额度校验。预览计入本单已有明细与本次导入，仍不预占库存；最终保存重新计算。

### 5.3 回收原料的后续使用

回收RAW在来源批次OPEN期间可查询，但不能出库、移转、普通调整或归档。来源批次SETTLED后，作为同厂、同客户的原材料继续领用，使用原材料重量规则，不需要半成品释放，也不恢复来源释放额度。

候选返回只读来源工单/工序/批次及可用状态；实际保存、导入、调整入口执行同样规则，不能仅前端禁用。客户为空、不匹配、来源作废或来源待核对时拒绝领用，不根据相似名称猜测。

## 六、结算、总账、冲销和一致性

### 6.1 计算与展示更新

- `RawReturnAllowance`抽取/扩展为统一批次重量规则，旧原料/半成品还库都扣除P。
- `WarehouseService.settleInternal`及`SemiFlowService.verifyHistory`纳入新类型；报工仍保存实际总领料、产出及还库后损耗，不把回收记作新增半成品产出。
- `ProcessConsumptionService`和消耗表增加独立“加工余料还库(g)”及`processRawReturnedWeight`；原料还库列保持原义。当前工序已结算弹窗口径和隐藏入口保持不变。
- `WorkOrderWeightBalanceService`新增加工余料“累计回收 / 本单净再领用 / 净还库”三项及导出文案。识别新关系表后，来自同工单回收库存的领用与原料还库排除在整单外部原料领入/原料还库分项之外，归入`INTERNAL_RECOVERED_RAW`追溯，避免扩大整单新增投入。
- 整单加工余料净还库＝本单累计PROCESS_RAW_RETURN－本单从这些库存的有效领用＋本单对这些领用行的有效RAW_RETURN。例如回收10g，本单再领8g并还回2g，净还库为4g；三项保留明细，不能只显示累计10g。其他工单领走回收原料不冲减来源工单已回收重量，目标工单将其作为实际外部原材料领入。
- 批次平衡：I=O+R+S+P+损耗。整单不累加内部半成品流转为外部新增投入；余料库存不计本单半成品在库，不参加半成品自动释放。
- 报价、理论损耗公式、产品件数和计划不变，预警使用扣除实际回收后的损耗。

### 6.2 冲销和依赖

- 未结算且回收库存未被其他操作引用时，允许按现有权限冲销余料单：逆向扣回RAW库存、恢复本批次可还重量，保留追溯记录。
- 已结算后不单独改写损耗；走完整批次纠错/冲销，再重新录入。不得为方便补录自动解锁报工。
- 回收库存存在有效下游领料、原料还库、调整等引用时，阻止冲销对应余料单或整个来源批次，列出阻断单号；不能只检查当前余额是否足够。
- 下游按依赖逆序处理后才允许来源批次冲销，不自动级联删除，不将B工单损耗转回A。
- 同批次还库、产出、结算并发时使用相同工厂/批次/库存锁顺序，同类ID升序；候选接口不加写锁。UUID沿用仓储幂等，同UUID不同内容拒绝，旧请求指纹不因新增可选字段变化。
- 所有单据、库存、关系和结算变更同事务；失败全部回滚。新增还库类型沿用仓储录入权限，结算/冲销使用原独立权限，不自动新增角色授权。
