# 生产工单详情报工汇总竞态修复计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:executing-plans 按任务执行，先添加并确认失败回归，再实现与验证。保留现有工作区改动；不提交或推送GitHub。

**Goal:** 切换生产工单或重复刷新报工汇总时，只有当前工单的最新有效请求能够写回报工列表；加载失败不得被显示为没有报工记录。

**Architecture:** 保留当前复用的详情组件，给详情及汇总建立明确的请求归属和生命周期边界。汇总使用独立请求序号，同时校验工单ID、详情轮次及组件存活状态；分离详情与报工加载／错误状态。利用现有请求拦截器的isContextCurrent机制，忽略过期请求的普通错误提示，保留既有401会话处理。

**Tech Stack:** Vue 3、TypeScript、Element Plus、Axios、Playwright/Chrome。

**Spec:** 用户确认的故障分析及本文设计约定：A汇总迟到不能替换B数据；A非空但产品明细ID不属于B时，也不得把B列表过滤为空。本轮仅制定计划，不实施代码修改。

## 设计约定

### 请求归属

每次详情加载捕获当前工单ID与详情请求序号；每次汇总加载另捕获汇总请求序号和所属详情轮次。

响应仅当以下条件全部满足才能影响页面：组件仍存活；请求工单ID仍等于props.id及已加载详情ID；详情轮次未变化；汇总请求仍是最后一次。

成功、失败、finally使用同一有效性判断。不能只在调用loadReports()前检查，因为覆盖发生在其await完成后的赋值阶段。

汇总请求只能在当前工单详情有效加载后启动。报工弹窗changed、手动重试、首次加载均复用同一入口，不使用不同的写回分支。

### 切换和离开

props.id变化时同步使旧详情与旧汇总失效，清空旧报工及错误状态，重置产品标签，关闭旧报工弹窗，然后加载新工单。A→B→A仍须依靠序号区分，不能只比较ID。

组件卸载时使全部请求失效，禁止旧响应回写、弹出普通失败提示或恢复loading状态。返回列表后重新进入，即使工单ID相同也不能接收上一组件实例的响应。

### 加载与错误展示

- 详情与报工汇总分别维护加载状态；基础详情成功后可正常展示，报工区域显示自身加载状态。
- 切换工单时立即清空上一工单报工，加载期间不提示“暂无报工记录”或“加工批次结算后自动生成报工记录”。
- 同一工单刷新期间可保留上一次成功记录并覆盖局部加载状态；不会将其视为本次请求已成功。
- 最新汇总请求失败时清空待展示结果，显示“报工记录加载失败”及“重试”；保留已成功加载的基础详情，不误报整张工单加载失败。
- 仅在最新汇总查询成功且当前产品确实无记录时显示“暂无报工记录”及现有说明。
- 旧请求失败和旧finally不得清空当前列表、显示错误、关闭当前loading或影响重试。

### 请求辅助函数

为reportSummary(workOrderId,isContextCurrent?)增加可选上下文回调，调用方式向后兼容。详情orderDetail(id,isContextCurrent?)如需抑制离开后的旧详情错误，也增加同样可选参数；其余调用方无需调整。

继续使用现有请求拦截器；旧上下文普通业务错误、网络错误和追踪提示不影响当前页面。401仍按既有sessionToken隔离处理，不改变登录过期及退出规则。
