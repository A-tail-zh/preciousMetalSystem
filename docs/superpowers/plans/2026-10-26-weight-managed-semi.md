# 粉料半成品按重量管理与接入额度分离 Implementation Plan

**Spec:** 本文“业务规格”落实用户本轮请求和上一轮原因分析，是本计划的内嵌规格；不依赖将旧截图中的32解释为特定历史记录。

## 业务规格

### 1. 计量模式和字段语义

| 内容 | PIECE 按件管理 | WEIGHT 按重量管理 |
|---|---|---|
| 适用 | 成形件、有明确件数的半成品及现有成品 | 粉料等无自然件数的半成品 |
| 实测净重 | 必填，正数 | 必填，正数 |
| 件数 | 必填整数，沿用现有范围 | 选填；填写时为1～1000000整数 |
| 空件数 | 按件业务拒绝 | 表示未记录，不是零件，不补1 |
| 控制库存和流转 | 件数、净重双控 | 净重控制；件数仅作参考 |
| 生产件数守恒 | 连续按件加工范围内保持现有规则 | 不将参考件数用于产能、完成量或接入额度 |

- 以“工序产出的半成品”确定模式，不仅靠工序名称包含“粉料”判断。
- 产品工艺配置增加“产出计量方式”；新建及现有配置默认PIECE，用户为实际粉料步骤明确选择WEIGHT。
- 工单创建保存每步模式快照；批次、产出、库存、释放和领用关联保存或可靠引用同一快照。
- 修改产品配置只影响新工单。工单未发生业务时可通过受控编辑更新；已发生业务不得直接切换模式。
- 本期成品仍按件管理；最后一道成品入库的数量必填，不扩展成品按重量销售业务。
- 工单产品计划数量仍表示最终计划成品件数。重量型中间步骤不再要求完成相同件数。
- 必须区分当前工序的产出模式与每条领料的来源模式；可同时领取原料、重量半成品和按件半成品。

### 2. 参考件数的展示与余额处理

- WEIGHT页面使用“参考件数（选填）”，提示“仅作实物记录，不用于领用额度、工序完成或损耗判断”。
- 使用可空字段保存参考件数，不把空值装入现有严格按件的quantity计算中。建议新增reference_quantity，保留既有quantity字段供PIECE及旧请求使用。
- 库存、单据、导入导出均区分referenceQuantity与quantity；前端不向PIECE字段偷偷写0占位。
- 重量型库存的参考余额：余额及本次变动均已明确记录时可以相加减；任一缺失或出现不一致则显示“未完整记录”，不猜测余额。
- 参考余额不一致不阻止合法重量流转，也不产生负参考库存；记录未完整状态及依据。库存耗尽时参考余额清空。
- 库存调整允许明确补录参考余额，但不能反推历史批次完成量；保留调整前后值、原因、版本及审计。
- 原始入库记录与各单据参考件数永久保留，库存余额变更不覆盖它们。

### 3. 库存可领余额与跨单接入限制

库存物料行展示实物信息：

- PIECE：“库存可领：33件 / 600.000000g”。
- WEIGHT：“库存可领：600.000000g；参考件数：33”或“参考件数：未记录”。
- 跨单释放来源另外展示“释放可用净重”和来源工单、工序、批次。

工单层提示改为“跨工单接入”，与库存清单分区：

- PIECE连续按件链需要计划覆盖额度时，显示接入上限、明细占用及剩余，附计算依据。
- 普通本工单相邻工序领料不显示“本单已填0”的无关提示。
- WEIGHT不展示虚构的“可接入32件”；显示“按重量领用，受来源库存及释放净重限制”，并显示本单外部领用净重。
- 不凭空生成目标工单“可接入多少克”。现有工单没有粉料计划克数，不用最终成品数量换算重量上限。
- 跨单重量候选可领净重=min(来源实物净重，释放剩余净重)；同一单据多行共享额度。
- 按件候选继续同时受实物件数/重量、释放额度、目标计划覆盖余额限制。
- 前后端应按来源模式分别判断，不能对混合清单共用一个整数容量值。
- 库存调整更新实物余额，不改工单计划或历史报工；切换上下文及点击刷新都重新取得各自口径，不复用过期响应。

### 4. 对领料的影响

- 原材料领料保持现状。
- WEIGHT半成品领用必填净重，参考件数可空；净重不超过来源余额及有效释放额度。
- PIECE半成品仍件数、净重双控；参考件数不得替代有效件数。
- 粉料参考1件不限制下道工序只能产1件；产出成形件仍受工单剩余计划和重量平衡限制。
- 连续PIECE来源加工保持产出件数<=净领用件数规则；存在重量转换时不建立粉料参考件数与成形件数等式。
- 混合输入逐行保存模式及来源，识别有效重量型加工投入；原材料补充仍不能增加纯PIECE连续加工的件数额度。禁止用微量附加原料或伪造重量模式解除原有件数限制。
- WEIGHT模式本身不授予跳步资格；仍执行路线及许可检查。

### 5. 对还库的影响

- 半成品还库恢复原来源库存、减少当前批次投入，保留来源身份，不自动释放。
- WEIGHT半成品按原出库行有效剩余净重控制，可分明细记录参考件数；件数空不阻止还库。
- 跨单WEIGHT还库恢复原释放记录的净重额度，不新建释放，不按参考件数恢复接入件数。
- PIECE半成品还库仍同时校验有效件数、净重与未加工余额。
- 加工后粉末、边角料转原材料走PROCESS_RAW_RETURN；不因形态为粉末就混同于未加工半成品还库。
- 一次余料确认可含原料、半成品及加工余料；同单共享重量额度，全部成功或全部回滚。
- 无余料只保存确认，不生成空白还库单；整批未加工继续使用批次冲销。

### 6. 对释放与库存调整的影响

- WEIGHT释放必填净重，件数选填，不因quantity为0或空而漏掉真实重量库存。
- 可释放净重=实物余额-已释放未使用净重；部分释放、领用、还库、撤销、冲销共用该口径。
- 参考件数不作为释放可用额度或“已使用”判定；是否使用以有效关联和净重判断。
- 正常完成新工单自动释放WEIGHT剩余净重；部分关闭与历史工单仍单独确认。
- 释放不产生实物库存增减流水，不抹除原工单绑定。
- 对尚有有效释放余额的库存，继续禁止普通库存调整、非生产出库及盘盈冲销绕过释放账。
- 修改参考件数也必须走已有调整权限及保护规则，不新增旁路。

### 7. 对结算与损耗的影响

- WEIGHT批次取消强制输入“实际完成件数”；结算产出由真实入库净重及余料确认确定。
- 批次有有效产出、已完成一次余料确认、重量平衡合法后可结算；已领未产的批次不能通过空件数或零产出结算。
- 批次仍允许分批；一次确认只结束当前批次，不自动宣告整个重量工序已经完成。
- PIECE批次实际完成件数仍等于有效产出件数，受工单计划余额和适用的净领用件数限制。
- 净投入=领料净重-原料还库-半成品还库-加工余料还库；损耗=净投入-有效产出净重。
- 实际损耗率继续为损耗/净投入×100%，同工序多批次采用合计值相除；零投入及异常关系显示待核对。
- WEIGHT批次不以参考件数计算g/件平均损耗或件数阈值异常；沿用当前g/件阈值的历史快照但显示“本工序按重量管理，件均预警不适用”。实际损耗与损耗率正常展示。
- 本期不擅自把g/件阈值改成百分比；如需粉料损耗率预警，作为独立明确单位及快照的后续规则。
- 最终成品数量、最终完成判定和原工单/领用工单损耗归属不混用参考件数。

### 8. 对工序进度和正常完成的影响

- PIECE步骤显示计划件数、本单加工件数、合法外部接入及剩余，保留连续按件链覆盖规则。
- WEIGHT步骤显示本单已产出净重、外部净领入重量、未结算批次数、剩余在制及状态；不以参考件数显示1/33或32件缺口。
- 已产出重量没有计划重量分母时，不显示百分比完成率。
- 增加“本工序不再继续投产”确认，针对重量工序保存状态、版本、操作者及原因。所有相关批次已结算/冲销、余料已确认后才能确认；有未结算批次时拒绝。
- 下一工序不必等待上一步所有批次结束，有有效、符合路线的半成品即可按批接续加工。
- 确认重量工序结束后禁止新增该步批次；重开受权限及下游依赖限制，不自动删除下游数据。
- 跨单粉料只记录真实领用净重、来源和已完成路线，不伪造前置加工件数、报工或损耗。
- 在路线中的重量转换点切断件数守恒。跨越转换点的前置步骤用“来源路线已覆盖/本单加工”展示，不能用参考件数生成数值覆盖；连续PIECE区间仍执行件数约束。
- 正常完成要求最终成品实际数量达计划、无未结算批次、重量步骤已完成投产确认或具有真实有效外部来源覆盖、来源依赖及重量总账合法。外部覆盖须有有效实领且被有效加工批次使用，不能空领后全额还库维持覆盖。
- 部分关闭保留现有实物核对与原因流程；不能用重量步骤结束确认替代工单部分关闭。

## 数据与接口设计

### 数据调整

新增迁移包含：产品工艺产出模式；工单步骤模式快照；批次计量模式；单据/库存/释放的参考件数及完整性状态；重量步骤投产结束记录及事件。

- 历史业务统一保持LEGACY_PIECE语义，不按名称推断转换；历史查询、旧幂等请求和旧指纹不变。
- 新模式字段由后端根据工单及来源取得，禁止客户端伪造模式绕过件数。
- 新WEIGHT请求使用referenceQuantity；旧quantity在WEIGHT新接口中不得被悄悄视为产出件数。兼容适配层明确区分旧请求与新请求，歧义请求拒绝并提示刷新页面。
- 若已有字段非空或约束限制空数量，新增字段/模式分支承载WEIGHT，不直接全局放宽旧字段校验。
- 所有SUM/COALESCE、number(null)、DTO原始long类型、Excel空单元格逐项审计，禁止抹去“未记录”。

### 接口

- 库存候选新增managementMode、availableNetWeight、availableQuantity（仅PIECE权威）、referenceQuantity及完整性提示。
- entryContext新增按来源类型的capacityKind、pieceEntryCapacity（可空）、实际外部领用净重和说明；保留旧字段仅供PIECE旧页面兼容。
- 保存/预览/导入支持referenceQuantity；WEIGHT明细不强制quantity；后端重取模式并重算共享额度。
- 批次/消耗/报工响应新增产出模式、实际产出重量、件数适用性及警告信息；保留旧字段供历史PIECE使用。
- 增加工序投产结束/受控重开接口，携带UUID、版本、原因和核对确认；落库与事件在同一事务。
- 释放接口根据来源模式分别校验净重或件数+净重；跨单领用关联及冲销恢复同事务处理。
- 导出数量列用空值或“未记录”，加计量方式、参考件数列；不把未记录导出成0。

### 一致性

- 固定顺序锁工厂、工单、步骤、批次、库存、释放记录；同类ID排序。
- UUID幂等，同UUID不同内容拒绝；重放不重新解释历史模式。
- 事务内重算同单多行及历史有效单据占用；编辑排除自身。
- 重量、库存、释放、接入依据、状态及审计关联同事务写入。
- 冲销以实际引用关系保护：重量领用、释放、步骤结束依赖均不能因空件数绕过。

- 旧1件、33件库存及报工原样保留，不静默重新解释成参考件数。
