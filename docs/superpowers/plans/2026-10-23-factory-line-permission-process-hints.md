# 工厂产线绑定、按钮权限与工序提示修改计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans，按任务逐项实施、验证并更新勾选状态。本计划不授权提交或推送 GitHub。

**Goal:** 工厂独立创建，产线负责选择所属工厂；无权限操作不显示；产品工序与理论损耗含义清晰。

**Architecture:** 保留现有工厂与产线数据关系，只收敛关系写入入口；业务页面使用响应式有效权限判断；产品编辑增加提示文案，不改变计算逻辑。

**Tech Stack:** Vue 3、Pinia、Element Plus、TypeScript、Spring Boot、MyBatis、JUnit、Playwright。

**Spec:** 本文“设计口径”对应本轮用户三项要求及两张截图，作为实施依据。

## 一、现状与设计口径

### 1. 工厂与产线

已核实：`FactoryRequest.productionLineIds` 必传；`FactoryService.create` 拒绝空产线；工厂编辑会执行清空关联后重新绑定。前端工厂新增、编辑均加载产线候选。另一方面，产线自身已经可以选择工厂，形成两处修改同一关系的入口，创建顺序也被倒置。

调整为：

1. 创建工厂只填写名称、占地面积、地址、简介，不再出现关联产线选择和对应必填校验。
2. 工厂编辑仅修改工厂基础资料；列表中的“产线名称”继续只读展示，没有产线时显示“暂无产线”。
3. 新建产线必须选择有效工厂。超级管理员可选择有效工厂；普通账号仅能使用后端限定的本厂，仍需对应产线新增权限。
4. 旧的未分配产线保留，不自动分配；在编辑保存时要求选择工厂。原有已绑定产线保持归属。
5. 产线跨厂移动仍仅限现有授权范围，保留生产工单引用检查、版本控制和事务；不能通过工厂编辑绕过。
6. 工厂无产线时允许保存；创建生产工单时若没有可用产线，提示“当前工厂暂无可用产线，请先在产线管理中创建并绑定”，不展示其他工厂产线。

**请求兼容约定：** 工厂请求省略 `productionLineIds` 或传空数组均可；非空数组明确返回“请在产线管理中维护所属工厂”，整次请求不落库。不能把空数组理解成解绑全部产线，也不能静默接受旧客户端的绑定请求。

### 2. 无权限操作隐藏

已核实：工厂按钮已有 `v-hasPermi`；该指令只在挂载时检查权限。工厂新增、删除服务还执行 `adminOnly()`。因此截图仅能证明界面可操作性与实际访问不一致，不能直接断言所有403都来自同一个接口；实施时须用账号和请求链分别定位。

统一规则：

| 情况 | 页面行为 |
|---|---|
| 缺少功能权限 | 不渲染按钮或操作菜单项 |
| 服务端已有明确身份限制，例如工厂新增、删除仅超级管理员 | 同时检查身份和功能权限，任一不满足均隐藏 |
| 有权限但未选择条目、正在加载或保存 | 保留按钮，按现有规则禁用 |
| 有权限但业务状态不满足 | 保留状态说明；按业务规则禁用，不伪装成权限不足 |
| 没有任何行操作 | 隐藏空操作列；批量选择列按实际批量操作能力显示 |
| 只有查看权限的状态字段 | 展示只读状态文字/标签，不显示可点击的启停开关 |

- 覆盖当前系统实际使用的基础资料、人员角色、生产工单、报工、仓储、报价、日志及预警页面，包含工具栏、行按钮、更多菜单、弹窗、抽屉、导入导出与批次结算等嵌套入口。
- 页面只判断本功能要求的权限，不因缺少无关的产品/工序管理查询权限而隐藏合法仓储录入入口。
- 组合操作按后端要求检查全部权限。例如新批次还料确认需要仓储录入与批次结算权限，缺任一则隐藏提交入口，允许查看时保留只读信息。
- 使用当前会话响应式权限数据，权限未就绪时默认隐藏；不把旧会话权限沿用到新账号。
- 前端保护只是交互控制，伪造请求仍由后端拒绝；不吞掉真实403或默认授予权限。

### 3. 工序与理论损耗提示

已核实：产品新增工序默认 `loss:'0'`；现有输入框已存在“理论损耗（g）”占位，但默认值使其不可见。`LossCalculator` 将理论值与单位平均损耗比较，因此字段单位应明确为 **g/件**。

确定文案：

| 位置 | 文案 |
|---|---|
| 分区标题 | 工序与理论损耗 |
| 工序字段标签 | 加工工序 |
| 工序空值占位 | 请选择加工工序 |
| 损耗字段标签 | 理论损耗（g/件） |
| 损耗空值占位 | 请输入每件产品的理论损耗 |
| 固定灰色说明 | 请按实际加工顺序添加工序；理论损耗为该工序每件产品的预计损耗，用于损耗预警比较，实际损耗以报工结算为准。 |

- 保留合法默认值0，不为了显示占位而清空已有数值；固定标签和灰色说明在有值时继续显示。
- 保留非负数、现有小数精度、重复工序限制及上移/下移行为；0的含义为理论损耗为零，不等同于未填写。
- 同步无障碍名称和错误提示中的单位；只读产品详情也能看到说明。
- 不修改理论损耗加容差的现有预警规则，不将产品资料修改回写到历史工单工序快照。

## 三、重点验收矩阵

| 场景 | 预期 |
|---|---|
| 新建无产线工厂 | 成功，不请求产线候选 |
| 工厂编辑保存，原有两条产线 | 两条归属均不变 |
| 旧客户端试图在工厂请求中绑定或转移产线 | 明确拒绝，基础资料也不部分保存 |
| 新建产线不选工厂、选择无效/跨厂工厂 | 按身份与范围拒绝 |
| 有历史工单引用的产线改归属 | 保留原阻断规则 |
| 无任何写权限账号 | 无新增/编辑/删除/提交等写入口，无空操作栏 |
| 有操作权限但没选择列表项 | 按钮保留并禁用 |
| 普通账号只有工厂新增权限标记 | 因后端超级管理员约束隐藏新增，不修改其权限 |
| 合法编辑账号缺无关主数据查看权限 | 仍能通过最小候选/上下文完成合法操作 |
| 切换账号或权限未就绪 | 不闪现旧权限按钮，不保留旧弹窗提交能力 |
| 理论损耗默认0或已有数值 | 标签及说明可见，数值不变 |
| 工序排序、产品保存、历史报工 | 原业务行为及历史值保持 |
