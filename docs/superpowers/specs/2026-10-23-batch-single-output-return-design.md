# 加工批次一次入库、一次还料确认与自动结算设计

日期：2026-10-23。状态：实施计划依据；本次只编写文档，未修改代码或业务数据。

## 用户已确认规则

- 次数按加工批次限制，同一工序允许多个批次。
- 每个批次一次产出入库、一次还料提交；一次提交可以有多条物料明细。
- 没有余料时允许确认“无余料”；有余料时一次提交全部还料。
- 一次产出满足该工序剩余制造数量时，无需再建立加工批次。
- 入库与还料确认完成后自动结算当前批次，进入后续流程。

## 实施口径

采用“单次产出入库 + 统一还料确认 + 同事务自动结算”。现有原料还库、半成品还库、加工余料还库保留各自库存及来源语义，由统一还料确认一次提交、按既有单据类型生成多张关联单据。相比仅在前端禁用按钮，本方案可覆盖导入、旧接口、并发及冲销；相比引入全新混合仓储单据类型，能够复用原有流水和报工计算。

先登记一次产出，再确认全部还料或无余料。产出件数由有效入库明细合计得到，不再要求重复填写实际完成数量。产出不足计划时仍可结算本批，工序剩余数量可另建批次；达到计划时禁止多建超额批次。没有实际产出时沿用完整批次冲销，不生成零件数报工。

“下一步”指已结算产出具备被后续工序领用的资格，不自动建出库单或扣库存，不绕过前置路线、跳步许可、来源、客户和工厂校验。部分数量完成时只放行已有合格库存，不将整个工序标为完成。末工序沿用现有整单完成及自动释放判定。

无余料是人工实物核对结论，不由重量差额自动判断，不创建零重量虚假还料单；剩余重量差额仍按现有公式计损耗。

为保护历史多次入库/还库记录，新建批次启用新策略，已有批次继续原策略，界面标明。历史请求原样重放；新策略批次不能通过旧入口绕过限制。

不修改历史记录、现有账号及角色权限，不自动提交或推送 GitHub。结算继续要求现有独立结算权限；不能以“自动”作为绕过权限的理由。前端切换、关闭、离开页面均使旧请求和确认框失效。

## 未采用的方式

- 仅按还库类型各限制一次：会允许一批多次还料，不符合一次提交全部的规则。
- 产出达到计划立即结束：会阻断随后还料，不采用。
- 自动将重量差额认定为无余料或自动生成还料：系统无法确认现场实物，不采用。
