## 问题、修复与复查

### 第一轮确认问题与修改计划

1. 浏览器回归的部分测试将导航地址固定为 5201 或 5173，不能随测试配置切换端口，导致连接拒绝或访问旧构建。修复：导航统一使用 Playwright 的 baseURL，Cookie 域行为保持原有约束。
2. 仓储库存候选接口返回预留重量，却未返回预留件数，按件库存的前端校验会把待确认出库占用算作可领件数。修复：在原查询中补齐 reservedQuantity 和 availableQuantity，不改变账务逻辑。
3. 仓储实收确认的预留复核仍将所有 RAW 当作按重量库存，与新可配置按件原料规则不符。修复：沿用共享 InventoryMeasurement.weight 判定，补充按件越额与历史按重量兼容的回归测试。
4. application-metal.yml 的业务连接默认 3306，Flyway 默认 3308；直接启用 metal profile 且未传 MYSQL_URL 时会把迁移和业务连接到不同实例。修复：统一默认端口为本项目 3308。

以上改动不改变接口名称、历史迁移或历史计量快照；调用链覆盖库存选项、前端余量校验和仓储实收确认。测试及复查结果见下文。

- 独立挂载的测试组件缺少路由上下文，库存页还要求真实列表路由和已加载身份；测试改为提供路由上下文，库存调整使用实际库存页面挂载，保留验证目标。

### 第三轮：请求边界与构建复查

- JSON 请求校验原先使用 readAllBytes，在解析和字段约束前无上限分配内存；匿名登录同样经过该入口。修复为最多读取 10 MB + 1 字节，超限返回 PayloadSize 字段错误，不依赖客户端 Content-Length。补充超限拒绝和边界内容原样传递测试，先复现失败再修复；真实匿名登录接口也验证拒绝超限请求。文件上传仍沿用其单独的 multipart 限制。
- Vue 补丁版本的类型检查发现设置组件两个无值 class 属性被视为布尔值；移除这两个无效属性后，类型检查和生产构建再次通过。
- 复查库存预留确认、候选返回、计量来源及其调用方：复用服务端不可变快照推导的计量方式，未接受客户端指定有效计量方式，也未改变库存账和历史快照。

### 第四轮：历史记录兼容与回归收敛

- 原料入库的旧修订记录缺少 category 时，仓储详情将未知类别默认当作按件物料，误显示“0 件”。修复在原料入库上下文补充 RAW 类别，继续由共享计量规则决定是否管理件数；明确标为 PIECE 的记录仍显示件数。覆盖缺少类别及明确按件的两例历史记录。
- 继续逐项复查全量浏览器失败，补齐当前接口所需的工厂、仓库、金属名称与统一出库提交响应；保留权限、竞态、历史兼容、额度和失败恢复断言，不跳过失败测试。

### 第五轮：延迟身份响应与草稿候选检查

- 稳定复现同一 token 的 getInfo 延迟成功到达 401 之后，会将 sessionReady 重新置为 true。给身份请求增加会话失效轮次快照，在 401、登录开始与清空身份时推进轮次，旧身份响应不能重新启用已过期会话。
- 新增金属后，产品/物料草稿的后台候选检查将自身修改误认为外部变更，导致保存按钮被锁定。子组件仅在主动新增/删除成功后通知父组件更新金属候选基线；操作期间暂停检查，旧检查以基线身份失效。产品基线保留既有密度快照，并按服务端左连接契约补充新金属的空密度、版本 0 行；真正的外部规则或候选变更仍触发冻结。
- 三个用例先全部失败，修复后全部通过；浏览器夹具同步真实 product/calculation-rule 返回的未配置金属行。继续复查全部身份场景、草稿竞态、目录删除、后台候选变化及页面布局，并重新构建前端快照。
