# P4旧入口、统计与完工核对草稿

日期：2026-11-12。本文汇总子任务核对、改造及收尾时复核的主代理真实HTTP证据；完整验收以主代理最终P4文档为准。未连接正式业务库、未清理历史表或切换正式服务。

## 1. 当前入口及保护

| 入口 | 实际服务端约束 | 本轮结论 |
| --- | --- | --- |
| `/metal/production-batches`创建/START_STAGE | BatchService生成PB；冻结路线及工厂/计划/版本；Execution.createForBatch只按有序节点进入 | 唯一新生产身份入口，继续保留 |
| `POST /metal/production-order/{id}/executions` | Execution.create仅允许原成功请求重放，其余明确拒绝并提示先建PB | 不能借旧加工记录创建API新建无PB活动 |
| `PUT /metal/production-order/executions/{id}` | 新PB关联记录拒绝旧入口改计划；只兼容历史未映射空记录 | 不以编辑加工记录改写PB目标 |
| 仓储`PRODUCTION_OUT` | ensureExecutionForOutbound要求已有OPEN加工记录；batch由记录读取并验证ACTIVE；无execution时拒绝 | `NEW`参数不能触发隐式建批；不信客户端自填batchId |
| 生产入库/退料/回收 | linkedExecution核对工单、产品组、节点、人员、OPEN及实际ACTIVE PB；具体来源另验slice和carry | 不能用普通仓储请求跳过PB阶段规则 |
| 加工记录close/cancel | 本轮复用bindDocumentBatch核对客户端batchId与实际ACTIVE PB；随后仍检查版本、加工责任、待办、实物及carry | 已退出/已完工PB不能继续从旧操作接口结算或取消；伪造batchId拒绝 |
| 工单编辑/删除 | ProductionOrderService.lockEditable要求CREATED、未实领、无PB及相关待办；Create/Edit DTO没有任意status写入 | 不能通过编辑/删除重置已有PB路线或直接伪造COMPLETED |
| 新仓储CSV | 前端解析后仍走`/metal/storage-orders`真实创建、预占与审核 | 导入内容不能跳过同一服务端身份/份额校验 |
| 新仓储export/列表 | GET查询，无建批或仓储过账动作 | 只读保留 |

历史NULL批次记录可以继续按既有兼容范围读取和处理，但不能领用新PB专属份额，也不能为新数据隐式生成另一套身份。P4不进行猜测映射。

## 3. 本轮统计修复

1. 看板生产进度此前只累加OPEN/CLOSED记录的`output_quantity`，遗漏`SPLIT_TRANSFERRED`已完成30件。现在按同工厂/工单/产品组/节点的有效OUTPUT事件聚合，包含OPEN/CLOSED/SPLIT_TRANSFERRED；INPUT、反转事件、取消记录和他厂记录不计。
2. 工序与工单正常完工覆盖同样改用有效OUTPUT事实，不靠可变汇总counter推断已产数量。没有真实OUTPUT的空CLOSED记录不能满足必需工序；移交前30件保留并只计算一次。
3. `stepSummary.inProcessQuantity`从实际INPUT+carry-in−carry-out−OUTPUT−有效RETURN/RECOVERY计算，不再用计划减产出冒充实际在制。例如计划70，退2件，后续产68件后实际在制为0，目标差额仍为2。
4. 首页损耗趋势、工艺排行及工厂损耗此前仅读退休`metal_work_report`，遗漏新执行确认损耗。当前看板改为新CLOSED加工记录的确认`loss_weight`及`closed_at`；不将旧报工与新执行相加。旧报工数据仍保留原查询，不因此删除。
5. `flow/report.executions`附带实际batchNumber；batchId、carry字段保持，前端区分PB生产身份与ST实物身份。

重量在制仍按INPUT+carry-in−carry-out−OUTPUT−RETURN−RECOVERY−确认LOSS计算。整单carry内部转出转入抵消；外部投入只来自真实外部来源领料，不把每一道内部领料重复累计为投入。拆合边、身份转移及计划不作为产量或库存新增。

## 4. 完工边界

工序结束只处理本条加工活动；PB完工、工单正常完工、异常完工审批和材料欠料是不同事实。

- 活跃PB（包括无目标但尚未处置的RETURN_RESIDUAL）、OPEN加工记录及待处理仓储单据阻止工单完工。
- 必需节点按真实有效OUTPUT或原有明确承接事实核对，不能用父子计划相加、空记录或缓存产量代替。
- 每个产品组分别达到目标，某组超产不能覆盖另一组缺口；原有合法超产处理规则保留。
- 98件不能正常完成100件目标；拆合、撤销与完工均不自动核销材料欠料。
- 空加工记录取消使用有效历史：只有相关仓储事实已完全冲销、实际件重/carry均清零且没有有效待办时，才可忽略已冲销的历史事件及已过账反向单据。仍有有效INPUT/OUTPUT/退料/carry或待办就拒绝，不能把INPUT=0但carry-in=700的承接记录当空记录。
- 编辑继续保留“曾发生历史就不可编辑”的保护，不因完全冲销而重写原加工计划。`flow.started`也保留曾经发生历史的事实；它与`canCancel`分别表达历史和当前可操作性，不因冲销回写成“从未开始”。
