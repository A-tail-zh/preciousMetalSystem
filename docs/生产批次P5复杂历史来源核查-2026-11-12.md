# 生产批次 P5 复杂历史来源核查

日期：2026-11-12。范围为本轮正式库只读快照在全新 3323 隔离 schema 中的来源证据核对；不对正式库执行来源核查，不改账、不批量映射、不猜单件来源。

## 工具与边界

工具：`tools/production-batch-p5-full-provenance.mjs`、`tools/ProductionBatchP5FullProvenance.java`。本轮输出均放在 `.runtime/production-batch-p5-full-history-20261112/provenance-*`，与先前 P5 证据分开。

运行前由主验收提供已恢复的新隔离库私有环境文件。本轮使用稳定的 V80 原始恢复库，不升级该库。设置 `P5_FULL_PROVENANCE_ENV_FILE` 后运行：

```text
node tools/production-batch-p5-full-provenance.mjs <schema> .runtime/production-batch-p5-full-history-20261112/provenance-evidence.json
```

工具强制校验 127.0.0.1、3323、指定新 P5 schema 与输出路径，以只读 REPEATABLE READ 事务查询。仅投影内部 ID、枚举和计量值；不输出客户/人员姓名、手机号、凭据、业务备注、快照 JSON 原文。输出文件使用 CREATE_NEW，避免覆盖先前运行。

工具源码的自检覆盖精确来源、历史歧义及重放失败的分类分支；已使用现有项目依赖编译通过，不引入新依赖。生产来源重放调用现有 `ProductionSourceBalances`，只读事务使 `ProductionBatchMaterialService.currentRead` 去除 FOR UPDATE。V80 无 batch_id 时，只读 JDBC 适配将其专门的查询替换为 SELECT NULL，进入历史来源分支；不创建字段、不模拟已建立新批次。不存在新来源表时明确记录 absent，不生成来源。有效 INPUT 另调用现有来源图环校验。

## 证据口径

| 对象 | 核查证据 | 不能据此推断的事实 |
| --- | --- | --- |
| 历史加工 | execution、全部有效/冲销事件、来源重放净投入/剩余及有效 OUTPUT/RECOVERY 来源 | 当前余额为零不代表从未加工；重放通过不代表新批次可写 |
| 原料和半成品混合 | 同 execution 有效 INPUT 的 stock.category、来源 owner、issue allocation、借料债务 ID | 混合池比例不能证明单件物理来源 |
| 跨工序 | INPUT.stock 对应有效 OUTPUT.execution 的冻结 order_step_id；并列 event 与库存快照 sourceExecutionId | 不能按工序名称或 execution ID 相近推断承接；同批次跨工序不是血缘自环 |
| 退料与冲销 | return allocation 对原 issue allocation 的引用、累计退料、storage event.reversed_by、加工事件 reversed | 退料后重放比例不能替代当时冻结产出来源；冲销不等于可删历史 |
| 借还 | issue 的 advance_debt_id/borrow_debt_id、debt 原始/剩余量及 settlement 引用 | 当前料权、欠料及历史供料来源是不同维度；还料不改写历史供料 |
| 退休旧批次 | process_batch、旧 inventory、warehouse_order/flow、work_report、batch_wip_balance、handover_allocation、process_raw_return_line | 旧 work_order/item ID 不能映射为新 order/item；JSON 存在不证明内容已核实；不恢复旧写入口 |

来源分类：

- `TRUSTED_EVIDENCE_CANDIDATE_NOT_WRITE_AUTHORIZATION`：已有批次关联，INPUT 有不可变来源分配及重量合计、目标 execution/root issue 证据，并且现有重放通过、未发现混合或来源冲突。只是可信证据候选，仍需计划、冻结路线、阶段、质量等映射核验；本工具不提供写授权。
- `HISTORICAL_READ_ONLY`：现有来源重放可读，但缺少新批次关联、不可变来源分配或混合来源的确切业务事实。保留历史读取；拒绝由重放结果自动生成逐件来源。
- `BUSINESS_VERIFICATION_REQUIRED`：现有来源重放拒绝；记录 execution/event/stock/issue IDs 与异常类型，需核实真实投入、退料时点、有效产出和来源链，不输出异常原文。
- `EMPTY_RECORD_REQUIRES_P5_CANDIDATE_SCAN`：来源工具识别无事件且投入量为零；本轮随后已与 working 库原 P5 扫描交叉核对，5条全部阻断。该工具编码不表示整体验收仍待扫描，实际原因见下表。

逐 execution 的 `missingFacts` 给出缺失事实编码；事件中保留库存来源候选 IDs、issue allocations 与不可变分配合计，供业务逐笔核对。多个库存生产者、半成品无有效产出来源、事件与库存来源 execution 不一致，均追加含 event ID 的原因，不任选一条。

## 人工核实与切换约束

历史可读与可写范围必须分开。缺少事实的记录保留原 ID 和账表，不借当前 owner 或池比例自动回填 material source，不复活退休批次。不属于本工具的计划/路线/质量及候选映射由主验收独立核对；只有完整来源证据与业务事实共同确认后，才可设计逐笔受控方案。
