# 全项目审查修改设计

日期：2026-10-14（Asia/Shanghai）。依据本次确认的10项修改计划实施。

## 边界

普通账号改密后注销全部会话；手机号同步登录账号并重新登录；管理员账号固定admin。保留旧账号、角色授权、业务数据和历史审计，不自动纠正历史手机号或回填历史日志。自动清理保持关闭，不恢复批次、预警规则、期初页面。本地提交，不推送GitHub。

## 认证与个人资料

新增sys_user.auth_version BIGINT默认0，登录缓存保存认证时读取的版本，鉴权同时检查账号状态、有效工厂和数据库认证版本。旧缓存缺失版本按0兼容；凭据或角色变更使认证版本递增，事务提交后删除相关Redis登录缓存，缓存重写不能使旧会话复活。

PasswordPolicy统一至少8位、最多72个UTF-8字节，不裁剪密码；旧密码只按数据库哈希验证。个人资料使用Profile请求模型，只允许version、nickName、phonenumber、email、sex。账号ID取登录身份，锁定并校验版本。手机号改变时同步user_name，管理员固定admin。资料响应返回version和requireRelogin，前端直接清理本地会话并跳转登录，不能依赖已失效令牌调用退出接口。

## 日志队列与清理

V19增加audit_outbox匹配索引(status,next_retry,create_time,event_id)、delivered_time和投递统计索引。队列按next_retry、create_time、event_id领取100条，使用FOR UPDATE SKIP LOCKED。正常批次同事务批量插入日志、scope和投递状态，事件ID唯一约束去重。批次失败回滚后逐个隔离重试，不修改原事件JSON；退避保持1、5、30、120、600秒。每轮最多1000条/2秒检查预算，调度间隔250ms。

清理历史增加stage、cutoffs_json、operation_count、login_count、runtime_count、outbox_count、update_time。阶段OPERATION、LOGIN、RUNTIME、OUTBOX、ARCHIVE、DONE；RUNNING/FAILED任务优先续跑，每轮最多1000条。截止日期首次开始固定。只有全部阶段完成才SUCCESS。归档仍先验证哈希、实际条数、ID集合及清单后删除；未投递事件不清理。

## 权限与仓储

报工详情增加batchVersion、batchStatus；报工纠错直接携带该版本调用批次冲销，不读取隐藏批次页面接口。查看需要work-report:query，纠错同时需要process-batch:reverse。库存添加统一使用warehouse-order:add，期初权限只保留后端兼容入口。

导入保留file、factoryId并增加warehouseId、type、适用的workOrderId/itemId/processId；模板表头保持不变。后端逐行验证本厂、库房、来源状态、产品关联、类别、数量、毛重减杂质和退还累计上限，生产关联只读取，不创建批次或单据。返回choiceId、code、name、specification和字符串ID，编辑无需重选，前端追加前检查合计1000行。确认过账时再次校验。

人员删除新增工单负责人、提交人和审批历史引用检查，连同原仓储、预警保护一起执行；批量任一失败全部保留，使用与工单写入一致的工厂和人员锁顺序。

## 测试与上线

完整后端回归、前端生产构建、个人改密与手机号浏览器跳转、导入编辑及权限浏览器测试、真实接口跨厂保护、正常日志与报价审计回归、一万条隔离队列并发/重启/重复/坏事件验收。V19前完整备份，迁移后原业务数量与余额流水核对，重启验证持久化。验收结果见全项目审查修改验收.md。
