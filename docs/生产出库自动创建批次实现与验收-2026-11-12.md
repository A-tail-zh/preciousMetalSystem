# 生产出库自动创建批次实现与验收

日期：2026-11-12。用户决定：生产批次在生产出库时自动创建。已实现并更新本地5173页面及8080后端，本次无数据库迁移，仍为V85。

## 使用方式

1. 仓储工单管理中添加“生产出库”，选择生产工单。
2. 无可用开放加工记录时，默认“出库自动建批”；只有一个产品组时自动带出产品组、首道工序及产品组目标件数，用户可修改本批计划件数。
3. 选择加工人员、仓库并填写物料。确认第一条物料且库存预占成功时，系统在同一事务创建统一生产批次及首道加工记录；无需先到生产页面建批和进入首道工序。
4. 继续添加明细沿用本次批次。复验人员沿用指定加工人，保存、提交与实际复验仍按原仓储规则进行。
5. 已有开放加工记录时默认已有批次领料；补料选择“已有批次领料 / 补料”，不会再建批。

例如总目标100件：若本次需要独立生产30件，将本批计划设30；后续另建独立70件批次时选择自动建批并填70。若只是一个100件批次分次领料，计划仍填100，后续补料沿用同一加工记录。计划件数不能从领料克重推算。

## 业务边界

- 自动创建的是现有统一生产批次，不新增另一种批次模型。后续跨工序、拆分、合并、追溯继续使用相同身份。
- 自动创建仅限冻结路线首道。后续工序沿原批次流转，不能借新出库跳工序、重复生产或覆盖历史承接。
- 所有计量工序都须明确本批目标件数，仍核产品组剩余计划份额、工厂、工单状态、冻结路线及加工人领料复验权限。
- 仓管使用已有出库新增权限触发受限的自动首道创建，不因此获得独立生产管理、任意工序开工或跨厂权限。
- 首次预占失败、人员无效或后续校验异常时，整个事务回滚，不留下批次、加工记录或占用。请求结果未知继续核实原请求，不能盲目换UUID再建批。
- 未保存单据取消或切换领料方式时释放占用；自动加工尚无实际流水、有效关联单据、其他有效预占或库存责任时，取消空加工及其空批次，释放计划份额。
- 已保存草稿的责任不因关闭编辑窗口而丢失；已实际领料的批次不会被自动取消。另一个有效补料预占也能阻止误取消。
- 窗口失联后的预占按原有效期处理；未用的开放加工仍可查询和选择，不把预占到期当成实际生产或擅自清理有单据的责任。

| `ProductionBatchService.java` | 复用统一建批校验，提供仓储事务内的首道自动创建；普通生产入口原权限保留 |
| `ProductionExecutionService.java` | 明确NEW模式建立PB和首道加工，EXISTING沿用原记录；空自动加工清理同步处理空PB |
