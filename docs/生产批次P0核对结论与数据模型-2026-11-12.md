## 1. P0结论

本次确定以下技术基线，供P1结构设计与后续实现使用：

| 决定 | 具体结论 |
| --- | --- |
| 唯一生产身份 | 新增生产批次；现有execution保留为工序加工记录，不恢复旧process_batch作为新模型 |
| 库存身份承载 | 现有stock是唯一仓库实物总账；stock下增加批次份额，不复制stock、不伪造入库 |
| 料权分区 | 份额同时分区当前owner；当前料权与历史材料来源成分分别保存 |
| 已完成/在制承接 | 原加工记录以SPLIT_TRANSFERRED非损耗移交结束；剩余在制转入子批次的新加工记录 |
| 历史事实 | 不复制或改归属原INPUT/OUTPUT；以产出份额分配及在制转移连接结果 |
| 纯拆合 | stock物理量、stock-owner总量、工序产出及债务均不增加；只转移身份和来源份额 |
| 合并身份 | 新批次可持多个stock份额，无须压成一个虚构stock |
| 旧入口 | 源码中前端过滤、服务端全局503均已存在；维持退休，不为本需求恢复旧前缀 |
| 来源重算 | 必须纳入份额和在制转移，不能继续只用stock整体池推算指定份额；后续退料不能倒改历史产出来源 |

以上是本次技术选型，不表示新增业务归属规则已获得确认。计件欠料抵扣、损耗承担、产出料权等沿用已核实的既定规则；未知情形不得以本设计补猜。

## 4. 计量、阶段和身份规则：PL-02基线

1. ID对外为十进制字符串；净重为g，两位小数字符串；实际件数为受范围校验的整数。
2. plannedQuantity是生产目标；quantity是实物件数；referenceQuantity是参考信息，不互相自动换算。
3. WEIGHT阶段的实际quantity对外为null，持久化沿现有0口径但通过measurementMode解释；不能把计划70填为实际70。
4. PIECE阶段实际件数由验收/交接证据提供；件数与重量分别核实。
5. 阶段使用工单冻结工序节点ID及顺序；不按工序名或processId集合去重。重复工序仍是不同节点。
6. 批次主表阶段只是摘要；真实可流转范围以库存份额和加工余额为准。部分完成时可同时有已完成库存与本工序在制，不假称整批完成。
7. 第一版合并限定同工厂、同工单产品组、同冻结路线、相同已完成阶段且质量可继续；不扩展跨工单合批。
8. 未经确认的损耗、料权、欠料归属不由比例猜测。拆分不等于确认损耗，合并不等于抵债。

## 5. 推荐逻辑数据模型：DB-01结果

以下表名是实施建议，不是当前已存在的DDL，不预占迁移版本。优先复用现有表；所有新关联都有factory_id和同工厂校验。

### 5.1 新增metal_production_batch：统一批次

| 字段 | 类型/含义 | 约束 |
| --- | --- | --- |
| id、factory_id | BIGINT身份及工厂 | PK；UNIQUE(factory_id,id)用于复合引用 |
| number | 可读PB编号 | UNIQUE(factory_id,number)，不解析编号推断血缘 |
| order_id、order_item_id | 新工单及产品组 | 同工厂且item属于order |
| route_snapshot_ref | 工单冻结路线/版本引用 | 不随产品目录后改而改变，复用工单快照 |
| planned_quantity | BIGINT，可空 | 正整数、适用上限沿项目约束；不直接入库存 |
| lifecycle | ACTIVE/SPLIT/MERGED/COMPLETED/CANCELLED/EXCEPTION_TERMINATED | 枚举约束；拆合原身份余额必须清零 |
| origin_action、origin_operation_id | INITIAL/SPLIT/MERGE/RETURN_RESIDUAL/MIGRATION及来源 | 是创建原因，不是第二种批次类型 |
| version、create_by/time | 并发及审计 | 非负版本，已发生事实不直接删除 |

不设置唯一processor_id或唯一order_step_id。位置、质量、阶段从真实明细派生，可缓存但不允许独立改写。

### 5.2 扩展metal_production_execution：工序加工记录

保留现有工单、产品组、工序、人员、实际INPUT/OUTPUT/RETURN/RECOVERY累计及原始事件。

| 扩展字段/能力 | 含义 |
| --- | --- |
| batch_id | 开工时所属生产批次，历史不改归属 |
| status新增SPLIT_TRANSFERRED | 已把剩余在制移交，非普通CLOSED，不自动计损耗 |
| transferred_at、transfer_operation_id | 移交边界与操作证据 |
| carry_in/out摘要（可派生） | 来自在制转移明细，不是仓储INPUT/OUTPUT |
| 余额查询及版本 | 以有效事件及转移计算；转移后原记录不得继续普通写入 |

历史execution允许batch_id暂空，明确只读/待映射状态，不强制瞎回填。新记录必须有关联。

### 5.3 新增metal_storage_batch_slice：库存批次份额

| 字段 | 含义 |
| --- | --- |
| id | stockSliceId，出库候选项唯一键 |
| factory_id、stock_id | 引用唯一现有stock |
| batch_id | 所属生产批次；UNASSIGNED时为空 |
| slice_kind | BATCH/UNASSIGNED，与batch是否为空一致 |
| weight、quantity | 当前份额余额，仅由关联流水驱动 |
| version、create/update_time | 并发及审计 |

所有纳入新流程的stock都必须有份额，包括未绑定批次的原料。旧数据未映射不等于可自由领用：UNASSIGNED再以migration映射状态限制历史不明生产库存；新增普通原料可按既有规则领用。

同stock、同batch唯一；UNASSIGNED也唯一。实现时用规范化batch键/生成列处理NULL唯一性，不能依赖MySQL允许多个NULL的普通唯一索引。不同来源贡献在子明细保留，不为每条贡献复制slice。

slice不另存可任意改写的stage；stock已冻结身份和完成阶段。份额所属批次的当前明细必须与stock阶段兼容。

### 5.4 新增metal_storage_batch_slice_owner：当前料权分区

主键(stock_slice_id,owner_id)，字段factory_id、weight、quantity。owner沿用0=工厂口径。其余额是现有metal_storage_ownership的批次分区，不是另一套可手工更改的料权总账。

没有owner分区时，A1可能领走属于A2的同stock料权，因此不能只做物理份额。

### 5.5 扩展现有metal_production_execution_operation：统一生产操作

复用其id、factory_id、actor_id、request_id、action、request_hash、result和请求唯一约束；增加reason、reversal_of、committed_at等实际需要的审计字段。新批次动作统一走此表，不再另建一套身份请求幂等库。

仓储和预占继续使用自身现有操作表；接口明确操作域，不互相查询错误请求表。纯身份操作不伪装成storage_event.INBOUND。

动作覆盖CREATE_BATCH、START_STAGE、SPLIT、MERGE、REVERSE_TRANSFORM、COMPLETE_BATCH及受控RETURN_RESIDUAL身份承接。仓储触发的身份分配在同一仓储事务记录，与真实storage_event关联。

### 5.6 新增metal_production_batch_edge：拆合来源关系

字段：id、factory_id、operation_id、source_batch_id、target_batch_id、planned_quantity_part（适用时）、quantity（可空）、weight、measurement_mode、allocation_basis、reversal_of。

- 一个操作可以一对多、多对一；不能只用parent_id。
- edge记录贡献，不记工序产出。结果ID均由服务端生成。
- 来源与目标不同，图无环；物理来源分别落下面的明细，不能只存一条无法核验的汇总边。
- 同批跨工序不产生batch_edge，不因batchId相同而误判来源环。

### 5.7 新增metal_production_material_allocation：实物与来源分配明细

这是不可变的分配流水，不是新实物总账。P1按实际查询优化物理字段，但至少保留：

| 字段组 | 必须能表达的事实 |
| --- | --- |
| id、factory_id、operation_id | 操作与分配身份 |
| storage_event_id / production_event_id | 若来自实际仓储或加工事件，引用真实事件 |
| from_slice_id、to_slice_id | 库内身份转移；仓储入库可只有to，真实出库可只有from |
| from_execution_id、to_execution_id | 在制移交、实际投入产出承接；与事件类型一致 |
| root_issue_allocation_id、source_allocation_id | 原始实际来源及上一份分配，链式追溯 |
| current_owner_id | 涉及库存身份转移时对应当前料权分区，与历史source_owner_id分开 |
| source_owner_id、source_kind | 历史供料来源轴；不等同当前slice_owner |
| weight、quantity、measurement_mode | 本次确切分配的件数重量 |
| purpose | RECEIPT_BIND/ISSUE_CONSUME/IDENTITY_TRANSFER/WIP_TRANSFER/RETURN/RECOVERY/LOSS/ADJUSTMENT/REVERSAL |
| allocation_basis、reversal_of、created_at | 实测、确认账面分配等依据及反向关系 |

采用明确用途的领域明细，不做可配置通用账本。每种purpose有唯一合法引用组合；例如IDENTITY_TRANSFER必须同stock两端，WIP_TRANSFER必须有来源/目标execution，不要求伪造document_id。

若一个实物分配包含多条源贡献，则逐贡献记录，合计才是本次转移总量。引用有类型约束，不接受一个无法外键核对的任意JSON来源。归属输出事件的原记录保留，输出份额转到A1即建立原OUTPUT→A1关系，不复制OUTPUT。

同一次操作的当前owner分区与来源成分必须能交叉核对；逐贡献明细求和只统计一次实物，不能将owner合计与来源合计再相加。WIP的可退未加工份额需另有remaining_returnable_weight/quantity及root_issue引用，可从有效分配流水派生；不能把全部carry-in都默认当成未加工可退原料。

两条轴分开：当前owner可能全部是客户，但产出历史成分仍包含工厂供料。不能用owner_id替代材料来源成分，也不能在拆合时覆盖stock.identity_snapshot的originCustomerWeight/originFactoryWeight。

### 5.8 在制转移主明细metal_production_wip_transfer

字段：id、factory_id、operation_id、source_execution_id、target_execution_id、order_step_id、weight、quantity（可空）、measurement_mode、allocation_basis、position_ref、processor_id、reversal_of、created_at。

源贡献通过material_allocation关联此transfer（增加wip_transfer_id外键）。它固定移交时点的来源，不按未来原issue的可变净余额反推。转移派生carry-in/out，不能重复增加INPUT/OUTPUT。

### 5.9 在原表增加关联

| 原对象 | 新增/调整 |
| --- | --- |
| 仓储单据及必要明细 | batch_id、execution_id双身份；库存返回结果中保存实际slice及来源映射 |
| 预占session上下文 | 目标batch、execution、type、customer、相关来源选择摘要；原请求及版本规则保留 |
| 预占行 | stock_slice_id；同一行绑定一份额，owner分配保留；同stock多份额用多行/不同reservationLineId |
| issue_allocation及退料引用 | 记录消耗的slice/来源分配；退料保留原issue和当前承接授权 |
| 生产事件 | batch_id可作为事件发生时快照，不能因拆分回写历史；carry用独立转移，不扩造假仓储事件 |

## 6. 余额及不变量

### 6.1 仓库实物和料权

对每个stock及适用计量维度：

```text
Σ slice余额 = stock物理余额
Σ slice_owner余额（按slice） = slice余额
Σ slice_owner余额（按stock、owner） = storage_ownership余额
纯拆合：同stock、同owner的转出总量 = 转入总量
```

真实领料同步减少stock、owner、slice、slice_owner各一次；供料来源份额同步消耗，损耗与实发/实收差异仍按真实仓储规则处理。

预占必须同时检查stock、slice、stock-owner、slice-owner四个余额，减去其他有效预占。已TEMP或BOUND占用的份额，第一版拒绝拆合，先释放/撤回，不暗中迁移别人的占用。

### 6.2 在制平衡

```text
当前加工可支配重量 = 真实INPUT + 有效carry-in
                    - OUTPUT - RETURN - RECOVERY
                    - 有效carry-out - 已确认损耗
```

转入/转出只算一次，汇总工单时彼此抵消；不算外部投入或工序产出。件数仅在实际计件且工艺不改变件数时按对应口径核对。

CHECK不能保证多行和跨表守恒。第一版沿用工厂锁，按工厂→工单/批次→execution→stock/slice→owner/原issue→预占固定分组、组内ID升序锁定；所有路径统一顺序。派生缓存和分配明细同事务提交，提交前检查守恒。

## 7. 100投入、30已完成、70在制的行级模型

以下1000g、300g、700g均为已核实示例，不是按件数比例自动算出的测量值。假定该工序已有实际件数、无辅料和损耗。

### 7.1 拆分前

| 对象 | 归属 | 实际事实 |
| --- | --- | --- |
| 批次A | 工单W | 计划100 |
| 加工E0 | A、S1、人员P0 | OPEN，计划100 |
| EV1 | E0，真实领料L1 | INPUT100件/1000.00g |
| EV2 | E0，真实入库O1 | OUTPUT30件/300.00g |
| stock ST1及slice SA | EV2产出，batch=A | 库存30件/300.00g |
| E0剩余在制 | 尚未完成S1 | 70件/700.00g，来源份额可核查 |

### 7.2 一次拆分事务

1. 锁定A、E0、SA、在制来源、原issue及相关占用，校验待处理单据。
2. 创建A1计划30、A2计划70，原A标记SPLIT。
3. SA转出30/300至ST1下A1份额；ST1仍30/300，owner总量不变。
4. A1关联EV2的真实产出，阶段为S1已完成，不新增OUTPUT。
5. 创建E2，batch=A2、工序S1、计划70、人员为本次有效接收人员。
6. E0→E2转移70/700及逐条来源份额，写WIP_TRANSFER。
7. E0状态SPLIT_TRANSFERRED，原INPUT1000、OUTPUT300及人员不变；carry-out700，余量0，损耗未新增。
8. E2真实INPUT=0、carry-in700，唯一当前在制责任为A2/E2。
9. 写来源边、操作结果和版本，整体提交。失败全部回滚。

### 7.3 后续独立生产

A1进入S2建立E3，batch仍A1，从ST1/A1份额真实领料。A2在E2继续S1，后续补料、产出、退料都记E2，不再写E0。

A2完成70件时记录新的OUTPUT70；S1完成量为原EV2的30＋E2产出的70=100。统计必须包含SPLIT_TRANSFERRED记录的有效OUTPUT，不能只求CLOSED记录而漏掉30。

两批均完成S2后合成B：B持有各真实产出的多个stock份额；A1/A2退出，来源贡献30、70；进入S3时B号不变。

### 7.4 后续退原料

E2退E0原领料的未加工部分时，保留原issueLineId/issueAllocationId，加carryAllocationId证明E2承接该份可退来源。当前RETURN记E2，原issue累计退量只增加一次。

不能只拿原issue总余额退料，必须同时检查当前承接可退量、真实原料形态、位置及工厂。已经加工的在制不能因源自L1就作为原样原料退回。

例：700g中确认20g未加工可退，则E2退20后余额680g；不能仍产出700g。件数是否随之变化由实际工艺/验收决定，不能由20g猜算。

### 7.5 为什么不能调用现有close或只加carry-in

现有close将input-output-return-recovery剩余当loss；若直接关闭E0，会把700g误记损耗。SourceBalances还会按原issue未来退料重算净来源，可能倒改E0已产30件来源。

因此必须同时实现：移交终态、carry-out、原投入责任承接、移交时来源明细、按实际事件顺序消费份额。后续退料只减少当前责任的剩余来源，不再次从E0历史OUTPUT或已转出的池扣除。

## 8. 所有仓储动作的份额规则

| 动作 | stock/owner总账 | 份额和来源 |
| --- | --- | --- |
| 普通原料入库 | 真实入库 | 建UNASSIGNED份额及owner分区 |
| 生产产出入库 | 真实入库，新合法来源stock | 建目标batch份额，来源绑定OUTPUT |
| 库内拆合 | 不变 | 转移slice、owner分区和材料贡献；不覆写stock整体快照 |
| 生产领料/交付 | 真实扣减一次 | 从选定stockSliceId消耗，不跨份额偷配 |
| 移库 | 走现有合法仓储路径 | 目标stock承接同批次及来源；不能只改slice位置 |
| 库存调整 | 仍走真实调整 | 同步slice及owner分区；增加量的来源依据不明则拒绝对应写入 |
| 料权调整/归还料权 | 走既定规则 | 同步slice_owner，历史供料来源不随owner变化而改写 |
| 冲销 | 反向现有真实事件 | 反向份额与来源分配，下游已用先逆序处理 |

### 8.1 退料身份选定规则

- 普通外部原料原样退库归UNASSIGNED，保留实际issue和当前责任追溯。
- 原生产批次仍有效且阶段兼容的生产来源实物，退回原批次的相应份额。
- 原来源批次已拆分/合并退出时，不复活它，也不把前道半成品退到后道批次并继承错误阶段。创建同一种生产批次的RETURN_RESIDUAL结果，继承原实物阶段及工单产品归属，关联原来源和本次退料。
- RETURN_RESIDUAL仅是创建原因，数量是原样实物返回，不新增工序产出，也不自动新增生产目标。plannedQuantity可空，禁止与工单计划相加；如果需要承担生产目标，走明确计划重分配，不直接编辑补齐。
- 无法证明来源、阶段和可退责任则拒绝，保留原流水等待核实。

## 9. 来源与统计实现约束

1. 物理库存来源仍以真实storage事件为准，身份流水不创建PHYSICAL/OWNERSHIP/DEBT变动。
2. OUTPUT、RETURN、RECOVERY和WIP_TRANSFER的来源分配在有效事件发生时确认并保留；后续退料不倒改过去。
3. 领用指定slice时按该slice的贡献明细消耗，不按stock整体混合比例偷换来源。
4. 混合后再拆只能保留有证据的混合贡献，不能声称每件精确来自某源。现行比例规则如复用，必须标记账面分配，并按尾差规则守恒。
5. 批次拆合图与加工/实物来源图分别检查无环；同batch的前后工序是不同execution。
6. 工序完成量只计有效OUTPUT；转移、来源边和父子历史都不计完成量。
7. 在制按carry后净余额计算，E0转出与E2转入不能重复计；工单外部投入不累计每道内部领料。
8. 正常完工、异常终止、产品交付、材料欠料分别判断。
