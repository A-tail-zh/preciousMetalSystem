## 3. 历史处理原则

1. 只对来源可证明的记录应用映射。无任何生产/仓储历史、无单据/库存/占用引用、无任何非零业务余额的空记录才可能成为自动候选；仍须核对工厂、订单产品项、冻结路线、阶段和计划容量。
2. OPEN空记录不能凭迁移补出“前序已完成”。有实际投入产出、冲销历史、混合来源、在制责任、粉料参考件数不明等情况，列待核原因，保持只读，不能靠猜测批次解除保护。
3. 扫描不回填；应用显式受控，在事务内重新核对清单和版本。幂等重跑不能重复创建身份或绑定。
4. 映射只建立身份/关联和迁移审计，不生成生产、仓储、借还流水。保留原业务事实和旧ID。
5. 更早退休模块的记录也需要歧义清单，不因没有新execution就推断没有历史在制。

6. 同产品项有非取消歧义记录时，其空OPEN兄弟也不能自动映射；同产品项全部未取消计划必须一起核算，不能按ID先给一条分配、把超额部分留歧义。两项均增加真实数据库断言。空CANCELLED不参与活动计划，可独立形成只读迁移身份。

工具采用 `tools/production-batch-p5-history-migration.mjs`、`tools/ProductionBatchP5HistoryMigration.java`，检查程序为 `tools/ProductionBatchP5HistoryMigrationCheck.java`。默认 `scan` 只读；`apply` 要求工厂、操作者、UUID、manifest及其哈希，工厂锁内重扫及核版本。仅支持本轮随机隔离库，当前不支持正式库apply。

## 4. 历史兼容接口增量

历史加工记录和生产单据使用以下标志说明状态：

| 字段 | 含义 |
| --- | --- |
| `batchMapped` | 是否已关联可靠生产批次 |
| `readOnly` | 是否因历史未映射而禁止新增生产写入 |
| `writeBlockedReasonCode` | 历史未映射返回 `LEGACY_UNMAPPED` |
| `writeBlockedReason` | 可展示的中文处理原因 |
| `sourceCompositionKnown` | 历史来源组成是否有可靠依据；未知不能当零或按总量推算 |

查询保留原投入、产出、损耗等事实。未映射的编辑、关闭、取消加工及新增生产单据不得经旧入口绕过规则。历史已过账单据的合法冲销，以及原草稿/待审单据的撤回、拒绝、取消、删除等清理，仍须遵守原权限、版本、下游和账实保护，不以“只读生产”全部封死。

关闭工序及正常/异常工单完工也核查未映射记录，包含CLOSED历史，不能只检查OPEN。取消仓储草稿时，未映射加工记录不被自动连带取消。仓储options不再提供未映射OPEN作为新增生产候选；普通UNASSIGNED原料仍按既有规则可用，历史生产库存仍受来源和阶段规则限制。

## 8. 切换准备及未放行边界

正式切换前仍需取得当前正式数据的受控一致性快照、完成全量歧义核查和在制处理、核实角色授权及环境配置、冻结写入并完成备份恢复验证。隔离合成样本通过不能替代正式历史全量迁移验收。

冻结后、尚无新业务写入时，可以在已证明数据一致且程序兼容的边界恢复旧服务；产生新生产批次、拆合、份额或承接写入后，不能宣称直接换回旧程序安全。必须停止新写入、保留新账并采用已验证补偿或向前修复策略。不得直接删新表、批量置空batch_id或恢复陈旧备份覆盖新业务。

未新增目标调整、异常批次终止或已关闭工序任意重开。实际98/目标100仍保持正常完工阻断；无撤销快照的旧拆合仍只读。这些边界不会因进入P5而自动解除。

实际CLI在产生新批次后已拒绝直接回旧程序；最终恢复库也验证新生产事实已经增加，`directOldProgramRollbackAllowed=false`。`check-old-program`检测到新PB即拒绝；没有检测到新PB也不构成发布或恢复许可，仍须核对其他仓储写入和完整冻结基线。

本轮结束仅关闭本次8100/6400/5269专属服务，保留3323实例、全部隔离库、私有备份及验证结果，见 `service-cleanup-proof.json`。没有正式数据写入、正式角色授权改动或正式服务切换。
