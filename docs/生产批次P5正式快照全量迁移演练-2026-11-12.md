歧义原因包括非零加工数量/重量/损耗、既有继承来源、事件与单据引用、同订单领用/库存/占用/欠料引用、已关闭或不完整路线、无法证明前序完成及计划容量等。即使某条自身当前重量为零或已 CANCELLED，也不能抹去同订单历史引用、猜测其来源。原因按 execution 和 factory 保存在 `migration-scan-summary.json`；详细 manifest 位于私有 `migration-factory-<ID>-manifest.private.json`。

上述原因码是当前“完全空记录”自动迁移的准入保护，**不是已确认的账务、路线或目标错误**。具体归因必须拆开核实：

- 真实历史包含 14 条跨工序记录；`PLAN_EXCEEDS_TARGET` 来自工具汇总未映射 execution 的计划后所作的准入诊断。跨道加工可能沿用同一目标，不能将跨道计划相加的结果据为原订单超产或目标设置错误。
- `INCOMPLETE_ORDER_PRODUCT_ROUTE` 是组合条件，也可能仅因订单已为 `COMPLETED`、不符合新建批次的准入状态而出现，不能直接认定订单、产品快照或路线缺失。
- `ROUTE_NOT_CONTIGUOUS_OR_CLOSED` 同时覆盖工序已关闭和序号不连续，出现该码不能直接认定路线序号错误；已关闭历史工序本身可以是正常业务事实。

真实差异以独立 236 项检查及人工核对的原始业务证据为准。本轮检查均为 0 差异；工具未准入的记录继续保留人工处理，不为通过扫描而放宽规则、重写计划或修改历史账。

由于 0 个安全候选，本轮调用 apply 阶段运行器仅进行范围/hash 校验、零候选判定和前后摘要断言，没有调用写入 `apply()`，没有新增技术审计或消耗 PB 编号。升级后全部 107 张 metal 表在该阶段内容完全一致。证据：`migration-apply-proof.json`、`migration-apply-business-before.json`、`migration-apply-business-after.json`。
